# 02: 邀请码领取无需预先绑定手机号

**What to build:** 未绑定手机号的用户可以从真实入口进入邀请码领取页，完成蛋宝宝领取及孵化体验；只有破壳成功并结束动画后，才进入统一的强制手机号绑定流程。前端与服务端采用一致的领取规则，已有手机号用户继续正常使用。

**Blocked by:** 01 — 破壳后强制绑定手机号闭环。

**Status:** ready-for-agent

- [ ] 未绑定手机号的有效微信账号可以从欢迎页进入首页、点击添加蛋宝宝并进入邀请码输入页，不在这些步骤要求手机号授权。
- [ ] 直接进入邀请码页、冷启动及返回前台时，尚未破壳的用户不会仅因未绑定手机号被送回欢迎页或拦回首页；静默登录及会话失效处理保持有效。
- [ ] 有效邀请码可在未绑定手机号时完成领取，前端和后端均移除邀请码领取的手机号前置条件；服务端继续校验真实登录用户、邀请码有效性及领养资格。
- [ ] 保持邀请码渠道限一只、原型占用、渠道互斥及重复领取规则，保留现有错误处理和数据归属约束。
- [ ] 领取后可完整体验既有孵化流程，包括命名、修炼及达到破壳条件后的破壳操作，不提前要求绑定手机号。
- [ ] 破壳动画结束且服务端确认成功后，未绑定账号进入任务 01 的绑定闭环；拒绝或绑定失败保留破壳成果，绑定成功后正常进入后续功能。
- [ ] 已绑定账号领取、孵化及破壳时不重复授权；演示快速破壳邀请码同样遵循破壳后的绑定时机。
- [ ] 先写失败测试再实现，验证未绑定账号从欢迎页经邀请码领取、孵化到破壳后绑定的完整路径，以及直接进入、会话失效、无效邀请码、重复领取和已绑定账号回归；同时验证服务端允许未绑定账号合法领取。
- [ ] 完成相关前后端回归及工程检查，变更逻辑的有效测试覆盖率至少 80%；日志和测试输出不暴露手机号、授权凭据或会话凭据。
- [ ] 同步邀请码领取及手机号绑定时机的现行说明，注明原领取前手机号设计已被新规则取代；保留历史记录。
