# 01: 内部游戏分类与存量兼容

**What to build:** 运营在智控台可以识别并维护内部游戏。升级后，既有游戏自动归为内部游戏，用户从百宝箱活动和小纸条仍可进入现有原生玩法。

**Blocked by:** None (can start immediately)

**Status:** resolved

## 验收标准

- [ ] 在含存量游戏的隔离数据库运行 Liquibase 迁移。存量记录的 `game_category` 为 `INTERNAL`、`jump_url` 为空，原有游戏类型、星星配置、每日上限、入口及启停状态保持一致。
- [ ] 智控台列表显示「内部游戏」。新增时默认选中内部游戏，编辑时回显分类。运营可按现有规则保存星星、每日次数和至少一个游戏入口，内部游戏表单隐藏跳转链接。
- [ ] 管理端保存、分页和详情按 `gameCategory` 和 `jumpUrl` 契约往返。旧客户端缺少分类的新增按内部游戏保存，缺少分类的更新可以继续修改已有内部游戏。游戏类型仍来自 `GAME_TYPE` 字典，每个游戏类型最多对应一条游戏配置。
- [ ] 百宝箱活动列表和小纸条的游戏数据均能返回内部分类，沿用原有启用状态、入口筛选和鉴权。用存量记录复查两个入口的一起画、听你说路由，以及未实现的内部游戏原有提示。
- [ ] 沿用游戏管理和小程序的测试入口，覆盖迁移、内部游戏保存和读取、智控台默认值及原生入口回归。
