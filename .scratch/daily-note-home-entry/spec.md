# 首页小纸条信封入口接入 (Daily Note Home Entry Integration)

Status: ready-for-agent

## Problem Statement

后端小纸条能力（当日内容查询、幂等打开、星星奖励、随机关联游戏）已全部就绪，但蛋宝宝小程序从未调用这些接口：用户打开小程序看不到当日小纸条，拿不到打开奖励，「连续陪伴天数」因没有打开记录始终为 0。打开接口 `POST /app/daily-note/opened` 返回空数据，前端无法向用户展示本次获得的星星数量。

## Solution

蛋宝宝小程序破壳后首页接入小纸条：左下角圆形入口位做二态切换——有未读小纸条时显示信封图标（右上角红点，附纸飞机抵达动画与音效），打开后当日恢复为聊天入口宠物 icon。点击信封弹出当日小纸条（标题、正文、节气、关联游戏邀请），弹出即调打开接口领取星星，弹层内展示本次获得的星星数并刷新左上角星星罐余额。关联游戏仅展示信息，点击提示"敬请期待"。后端仅做一处补缝：打开接口返回本次奖励结算结果，供前端展示 "+N"。

## User Stories

1. As a 已破壳用户, I want to 打开小程序首页看到信封入口和红点, so that 我知道今天有新的小纸条。
2. As a 已破壳用户, I want to 信封出现时看到纸飞机飞入动画并听到抵达音效, so that 新纸条的到来有仪式感。
3. As a 已破壳用户, I want to 点击信封看到当日小纸条的标题、正文和节气文案, so that 我读到宠物寄来的每日内容。
4. As a 已破壳用户, I want to 打开小纸条后立即获得星星并看到 "+N" 提示, so that 我明确知道奖励已到账。
5. As a 已破壳用户, I want to 打开小纸条后左上角星星罐余额同步更新, so that 余额展示与实际一致。
6. As a 已破壳用户, I want to 当天打开过纸条后入口恢复为聊天 icon, so that 我可以正常进入聊天页面。
7. As a 已破壳用户, I want to 次日进入首页看到新信封, so that 每天的打开机会互不继承。
8. As a 已破壳用户, I want to 纸条里看到关联小游戏的图标、说明和可赚星星数, so that 我知道有这个玩法。
9. As a 已破壳用户, I want to 点击游戏邀请时看到"敬请期待"提示, so that 我知道游戏尚未上线而不是没反应。
10. As a 已破壳用户, I want to 打开请求因网络失败时收到提示且红点保留, so that 我可以重试而不会丢失当天的奖励。
11. As a 已破壳用户, I want to 重复点击信封不重复获得星星, so that 奖励规则公平可信。
12. As a 未破壳用户（无宠物/孵化中）, I want to 首页不出现信封入口, so that 功能只在破壳后出现。
13. As a 运营人员, I want to 当天未配置小纸条或无可用游戏时小程序不显示信封, so that 内容空窗期不产生坏体验。
14. As a 后端维护者, I want to 打开接口返回奖励结算结果且重复调用幂等, so that 前端展示金额永远来自服务端事实。

## Implementation Decisions

### 已确认范围与规则

- 仅破壳后（存在 HATCHED 宠物）首页展示信封入口；未领养、孵化中不出现。
- 信封与聊天入口共用首页左下角同一个圆形按钮位：有未读小纸条显示信封（带红点），否则显示聊天 icon（现有行为不变）。不新增第三个悬浮按钮。
- 打开时机：点击信封先弹出纸条弹层，随即调用打开接口；不设"确认收信"按钮。
- 当天已打开后不可回看纸条内容；入口恢复聊天 icon；次日由服务端日期边界自动重置。
- 打开接口失败：Toast 提示，红点与信封保留，用户可重试。
- 打开接口成功：弹层内展示本次实发星星数（"+N"），并重新拉取星星罐余额刷新左上角。
- 关联游戏区块展示游戏图标（OSS URL）、说明、赚取星星数；点击 Toast "敬请期待"。游戏真实页面不在本期。
- 抵达动效：信封出现瞬间纸飞机飞入动画（约 1 秒）+ 信封抵达动效 + 播放抵达音效（InnerAudio，音量 0.25，遵守静音开关）。音效与动画资源从 UI 静态设计项目拷入小程序 assets。
- `POST /app/daily-note/opened` 响应由空数据改为返回每日奖励结算结果。三个非发奖分支（当天已打开、当日无内容、并发冲突）统一返回 `awarded=false, amount=0`，不多查历史金额快照——前端正常路径不会触发重复调用（已打开时当日查询返回空、不出信封）。
- 打开接口保持：无请求体、用户身份只来自 Token、日期只由服务端 Asia/Shanghai 时钟决定。

### 现有实现事实

- `GET /app/daily-note/today`：当日小纸条 + 随机游戏；已打开、无当日内容或无合格游戏时返回 `code=0, data=null`。VO 字段：date、title、content、solarTerm、game（游戏类型 code、图标 OSS URL、说明、赚取星星数、每日次数上限等）。
- `POST /app/daily-note/opened`：幂等标记已打开，同事务发放小纸条连续奖励（首日 11、连续 +1、封顶 17、中断回 11）。内部 `claimDailyReward` 返回的每日奖励结算结果已含 `awarded` 与 `amount`（含已领取时的金额快照），透出成本极小。
- 打开记录表 `(user_id, note_date)` 联合唯一；「连续陪伴天数」由打开记录现算——打开小纸条即累计陪伴。
- 首页数据加载链：`onShow` → 拉宠物列表 → 存在破壳宠物时拉星星罐余额；小纸条当日查询与之并列挂载。
- 首页左下聊天入口仅"在家"大场景显示（信封态沿用同一显示条件）；右下 AI 写真入口常驻，不受影响。
- 星星余额接口失败时前端静默隐藏星星行；小纸条查询失败同样静默回退聊天 icon。
- UI 静态设计项目已有完整设计稿：信封入口二态切换、红点、纸飞机动画（CSS keyframes）、纸条弹层结构（标题/语录/游戏邀请变体/关闭按钮）、信封图标资源、抵达音效文件。弹层设计稿中的记忆收集、互动反馈等杂项不搬。

### 接口契约变更

- `POST /app/daily-note/opened`：成功响应 data 由 `null` 改为每日奖励结算结果对象：`{ awarded: boolean, skipped: boolean, amount: number, transactionId: number|null, rewardId: number|null, rewardDate: string }`。前端只消费 `awarded` 与 `amount`，其余字段为未来调试与排查保留。

## Testing Decisions

- 只测外部行为，不测实现细节：接口契约（响应结构、幂等语义）与前端状态迁移（信封出现/消失、星星刷新、失败兜底）。
- 后端：打开接口返回值变更的单测与 HTTP 契约测试，覆盖首发返回金额、重复调用返回 `awarded=false, amount=0`、无内容返回 `awarded=false`。先行艺术：小纸条打开服务既有单测（幂等、并发、事务回滚）与每日奖励服务测试，沿用其替换时钟与数据库集成测试模式。
- 前端：小程序 utils 层 API 封装的单测沿用 `*.test.js`（node 直跑）惯例，mock request 层断言路径与响应处理；首页逻辑的测试沿用 `home.test.js` 既有结构，覆盖：有破壳宠物且有未读纸条出信封、已打开/无内容出聊天 icon、打开成功刷新余额与展示 +N、打开失败保留红点。
- 视觉与动效（纸飞机、红点、弹层样式）以对照 UI 静态设计稿人工验收为准，不写自动化断言。

## Out of Scope

- 小游戏真实页面与游戏完成链路（含游戏固定奖励的前端触发）。
- 纸条内容运营后台、AI 生成纸条。
- 已打开纸条的回看/收藏/历史列表。
- 智控台任何改动。
- 除打开接口返回值外的所有后端行为（奖励规则、连续计算、游戏随机选取均不动）。
- 弹层中静态设计稿的记忆收集、互动反馈、照片相关功能。

## Further Notes

- 小纸条奖励即「连续陪伴天数」的数据源：本功能上线后用户首页的连续陪伴天数才开始真实累计。
- 领域词汇以根目录 `GLOSSARY.md` 为准：小纸条、小纸条已打开、小纸条连续奖励、小纸条游戏、星星罐、游戏入口。
