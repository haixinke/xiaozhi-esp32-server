- 每个 provider 子目录内都定义一个 `class MemoryProvider(MemoryProviderBase)`，并通过 `super().__init__(config)` 传入配置，保持统一的构造签名。
- 在 `__init__` 中通过 `check_model_key` 校验 API Key，失败时记录错误日志并将 `use_xxx` 标志设为 False，使后续 `save_memory`/`query_memory` 直接返回空结果而不抛异常。
- `save_memory` 和 `query_memory` 均对输入内容执行相同的 JSON 包裹检测逻辑：若内容以 `{...}` 包围则解析并提取 `content` 字段，确保与 ASR 输出格式兼容。
- 查询结果统一按时间戳倒序排列（优先 `updated_at`，其次 `created_at`），格式化形如 `[YYYY-MM-DD HH:MM:SS] memory` 的列表字符串后返回。
- 所有 I/O 调用（网络 SDK、文件读写、LLM 请求）均包裹 try/except 并记录 `logger.bind(tag=TAG).error(...)`，异常不会向上抛出以保证调用方稳定。
- 日志统一使用 `TAG = __name__` 配合 `logger.bind(tag=TAG)` 的方式输出，区分不同 provider 的运行轨迹。
