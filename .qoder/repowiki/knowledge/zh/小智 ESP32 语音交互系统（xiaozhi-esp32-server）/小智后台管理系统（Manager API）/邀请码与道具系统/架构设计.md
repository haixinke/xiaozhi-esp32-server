模块按 invite 与 item 两个子包组织，各自遵循 Controller → Service(接口+impl) → DAO → Entity/DTO/VO 的分层结构。
- invite 子包：InviteController 暴露 /invite 路由，通过 InviteService 实现邀请码的个人/企业创建、分页、使用记录与统计；InviteServiceImpl 继承 BaseServiceImpl<InviteCodeDao, InviteCodeEntity>，复用通用 CRUD 与分页；邀请码唯一性由 InviteCodeGenerator 生成并通过数据库查重保证幂等；consume 操作通过 selectByCodeForUpdate + decrementRemaining 原子扣减，并用 InviteUsageEntity 记录使用流水实现幂等。
- item 子包：ItemController 暴露 /item 路由，ItemService 定义 SKU 列表、库存查询、grant/consume/owns 等接口；ItemServiceImpl 通过 ItemSkuDao/UserItemDao/ItemGrantLogDao/ItemConsumeLogDao 操作 ai_item_sku、ai_user_item、ai_item_grant_log、ai_item_consume_log 四张表；grant 基于 grant_log 的唯一索引 uk_source_ref_sku 实现幂等发放，并发冲突通过 DuplicateKeyException 捕获后回退更新；consume 对 outfit 类仅校验拥有不扣减，其他类型通过 UserItemDao.deductRemain 原子扣减。
- 依赖方向单向向下：Controller 依赖 Service 接口，Service impl 依赖 DAO，Entity/DTO/VO 作为数据载体，无循环依赖。
