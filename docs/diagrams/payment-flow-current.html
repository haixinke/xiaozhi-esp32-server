小程序微信支付流程 - 现有方案

完全依赖微信异步回调通知，回调失败时订单会错误超时

正常流程

  • • 用户下单 → 后端创建 PENDING 订单
  • • 后端调微信 prepay 获取支付参数
  • • 小程序调起微信支付控件
  • • 用户支付成功后微信异步回调后端
  • • 后端 markPaid → 履约 → markFulfilled

单点故障

  • • 完全依赖一条异步回调链路
  • • 回调地址错误/超时/被拦截都会失败
  • • 失败 15 分钟后订单被标为 EXPIRED
  • • retryPaidOrders 只处理 PAID 订单
  • • PENDING 订单不会被主动挽救

真实影响

  • • 用户已扣款但订阅未开通
  • • 商户已到账但系统无记录
  • • 需要人工对账、手动补单
  • • 用户体验差，投诉率高
  • • 财务数据与业务数据不一致
