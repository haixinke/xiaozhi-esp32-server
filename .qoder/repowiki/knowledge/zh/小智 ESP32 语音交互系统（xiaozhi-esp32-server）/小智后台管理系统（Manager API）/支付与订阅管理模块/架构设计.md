模块按 payment 与 subscription 两个子包划分职责，均遵循 controller → service(接口+impl) → dao/entity 的分层结构。
- payment 子包：PaymentController 暴露创建订单、查询、取消等 REST API；PaymentOrderService 封装下单、查单、主动查单履约等核心流程；FulfillmentDispatcher 作为履约调度器，根据订单 product_type 路由到具体履约实现（如 SubscriptionFulfillmentServiceImpl）；wechat 子包定义 WechatPayClient 抽象接口及 Mock/真实 V3 实现，支持通过 PayChannel 切换渠道；PaymentNotifyController 处理微信回调，PaymentCallbackLogDao/Entity 记录回调日志；PaymentOrderMaintenanceTask 为预留的定时任务（已注释）。
- subscription 子包：SubscriptionController 提供公开的计划列表与当前用户的订阅/权益查询；SubscriptionService 封装权益校验（requireFeature/hasFeature）；SubscriptionFulfillmentService 由支付回调驱动，完成 user_subscription 创建与 bonus_items 发放；SubscriptionExpirationTask 定时扫描过期订阅并重置 agent 初始态。
- 依赖方向：controller 仅依赖 service 接口；service impl 依赖 dao 和外部客户端（WechatPayClient）；payment 与 subscription 通过 FulfillmentDispatcher 松耦合解耦，避免循环依赖。
