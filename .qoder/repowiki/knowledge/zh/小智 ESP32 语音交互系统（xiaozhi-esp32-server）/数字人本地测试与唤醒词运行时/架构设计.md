模块由 Python 启动入口 `start.py` 统一引导，内部划分为两层：
- HTTP/WebSocket 服务层：`wakeword_runtime/runtime/http_server.py` 基于 `http.server.ThreadingHTTPServer` 自建轻量 HTTP 服务器，静态文件根指向模块根目录（`index.html`、`js/`、`css/`、`images/`），并在 `/wakeword-ws` 路径上实现原生 WebSocket 握手与帧编解码，同时暴露 `/health` 健康检查端点。
- 应用运行时层：`wakeword_runtime/runtime/app.py` 中的 `TestRuntimeApplication` 通过 `PluginManager` 管理插件（`AudioPlugin`、`WakeWordPlugin`），按 `priority` 排序执行 `setup/start/stop/shutdown` 生命周期；`EventPublisher` Protocol 定义事件发布接口，由 `WakewordEventBridge` 实现，使用线程安全的队列向多个 WebSocket 客户端广播消息。
- 配置与日志：`wakeword_runtime/config/` 下 `config_loader.py` 加载 `config.json`，`logging_setup.py` 初始化日志。
- 前端层：`js/app.js` 作为入口，依次初始化 Opus 编码器、音频播放器、MCP 工具、唤醒词桥监听器、摄像头与 Live2D 模型（`resources/hiyori_pro_zh`、`resources/natori_pro_zh` 下的 `.moc3`/`.model3.json`/`.motion3.json` 等）。`core/audio`、`core/network`、`core/mcp`、`ui`、`utils` 子目录职责清晰，依赖方向单向指向 `app.js`。
- 依赖方向：`start.py` → `runtime.app` / `runtime.http_server` → `bridge.event_bridge` / `plugins.*` → 底层 ONNX 模型与 sherpa-onnx 资源；前端 JS 仅通过 WebSocket 与后端通信，不直接依赖 Python 代码。
