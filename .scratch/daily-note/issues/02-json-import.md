# 02: JSON 导入与同日期覆盖

**What to build:** 运营在小纸条管理页上传 JSON 文件，一次新增多日内容或按完整日期覆盖既有内容。文件任一条目无效时显示可定位的错误并整批零写入；成功时显示新增数和覆盖数，文件未涉及的既有内容不变。

**Blocked by:** 01 小纸条手工管理

**Status:** ready-for-agent

- [ ] 管理端提供 multipart 字段 `file` 的 JSON 导入接口及智控台上传入口，沿用统一响应和超级管理员权限。
- [ ] 页面明确展示导入格式：顶层为非空数组，每项仅允许 `date`、`title`、`content`、可选 `solarTerm`；日期严格 `yyyy-MM-dd`，正文换行在 JSON 中使用 `\n` 转义。
- [ ] 提供可直接复制的两条示例：第一条含节气及两行正文，第二条 `solarTerm` 为 null；日期分别为 `2026-10-29`、`2026-10-30`。
- [ ] 文件仅接受 UTF-8、`.json`、最大 1 MB、最多 1000 项；空文件、空数组、非法 JSON、错误类型、未知字段及非 UTF-8 内容均整批拒绝。
- [ ] 手工保存的日期、必填、去首尾空白和 Unicode 字符长度规则同样适用于导入；节气不要求标准二十四节气名称。
- [ ] 文件内相同日期整批拒绝，不采用第一条或最后一条；尽可能一次返回数组位置（从 1 开始）、字段和原因。
- [ ] 校验通过后在单事务内导入；库内同日期整项覆盖内容并保留 ID、创建人和创建时间，其余日期新增；不触碰任何已打开记录。
- [ ] 成功响应及页面反馈包含 `addedCount` 和 `overwrittenCount`。
- [ ] 任一校验失败、数据库唯一键冲突或写入异常均整批回滚；并发日期冲突返回明确业务错误，不泄露 SQL 或堆栈。
- [ ] 先写失败测试再实现；Service 集成测试覆盖新增/覆盖计数、原记录身份与创建审计保留、未涉及记录不变、重复日期、未知字段、格式及资源限制、错误明细、零写入和数据库失败回滚。
- [ ] 智控台提供人工验证清单：合法导入、新增与覆盖统计、同日覆盖、部分无效整批拒绝、错误定位、文件外记录不变；不新增 Playwright。
- [ ] 现有前端测试、Vue 模板检查和生产构建保持通过。
