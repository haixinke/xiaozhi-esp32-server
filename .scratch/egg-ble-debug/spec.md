# 蛋宝宝小程序蓝牙联调页规格

Status: ready-for-agent

## 问题陈述

小程序与板端开发人员需要在微信真机上验证宠物蛋控制板的 BLE V2.0 协议。目前蛋宝宝小程序没有 BLE 联调页面。欢迎页的「进入快乐仙岛」按钮通往产品流程，已绑定手机号的会话还有可能在按钮显示前跳往首页。联调人员需要一个能直接进入、能在后端不可用时操作、能查到原始收发数据的临时页面。

## 解决方案

在开发版和体验版显式启动联调模式时，欢迎页显示「进入蓝牙联调」。点击后打开独立页面，由测试人员扫描、选择并连接一块控制板。页面自动完成协议握手，再开放查询、灯光和破壳控制。页面提供结构化设备状态、协议指令面板、单行原始指令输入，以及可复制的通信记录。

联调从手机到板端通过 BLE 完成。小程序应用层可照常在后台尝试静默登录，联调入口与页面都能在登录失败或后端停机时使用。

## 用户故事

1. 作为联调人员，我希望在开发版和体验版显式进入联调模式后看到「进入蓝牙联调」，以便从欢迎页进入测试工具。
2. 作为联调人员，我希望已有绑定手机号的会话也能留在联调欢迎页，以便复用同一台手机做回归。
3. 作为联调人员，我希望在后端停机或静默登录失败时仍能按原步骤连接板端，以便独立验证 BLE。
4. 作为蛋宝宝用户，我希望常规启动仍走现有欢迎页、首页和 NFC 领取流程，以便继续正常使用小程序。
5. 作为联调人员，我希望能开始和停止扫描，并看到附近设备的广播名及扫描标识，以便现场有多块样板时手动选择目标。
6. 作为联调人员，我希望能看到扫描、连接、握手、就绪和断开的状态，以便定位失败发生在哪一步。
7. 作为联调人员，我希望在蓝牙关闭、连接失败或特征不符时看到原因，以便调整手机或板端配置后重试。
8. 作为联调人员，我希望连接后自动读取 `INFO` 和 `STATUS`，以便在操作前确认协议版本和板端状态。
9. 作为联调人员，我希望看到完整 `SN`、固件版本和 `TYPE` 对应的宠物原型，以便把通信记录和样板实物对应起来。
10. 作为联调人员，我希望旧协议固件无法进入控制状态，以便及时更换支持 V2.0 的固件。
11. 作为联调人员，我希望能手动发送 `INFO` 和 `STATUS`，以便重复核对设备信息和实时状态。
12. 作为联调人员，我希望分别看到 `HATCH`、`MOTOR`、`FAULT` 和 `LIGHT`，以便区分动作记录、电机运行、故障和当前灯效。
13. 作为联调人员，我希望可选择协议定义的灯光模式并设置参数，也能单独关闭灯光，以便逐项验证灯效。
14. 作为联调人员，我希望灯光表单在发送前指出无效参数，以便将输入失误与板端拒绝区分开。
15. 作为联调人员，我希望在控制板允许时手动启动破壳，并看到动作受理和后续结果，以便核对一次性动作的状态变化。
16. 作为联调人员，我希望 `STOP` 能优先于正在发送或等待应答的普通请求，以便及时发送停止指令并收到对应确认。
17. 作为联调人员，我希望输入未知命令或错误参数并收到板端的 `!ERR`，以便验证板端参数校验和错误应答。
18. 作为联调人员，我希望长指令和分段应答能正常收发，以便用超过单包大小的报文验证完整链路。
19. 作为联调人员，我希望区分板端明确拒绝和指令结果未知，以便遇到超时或断连时先查设备状态，避免重复动作。
20. 作为联调人员，我希望记录按时间展示原始完整报文，并可展开分包与通知片段，以便定位传输、拼包或板端应答问题。
21. 作为联调人员，我希望能复制和清空通信记录，以便整理本轮证据并开始下一轮测试。
22. 作为联调人员，我希望切回前台时看到重新查询的状态，连接丢失时能手动选板重连，以便接着验证动作结果。
23. 作为联调人员，我希望退出联调页后释放连接和扫描，以便下一次打开时从干净的会话开始。

## 实现决定

### 入口与页面

- 以显式联调启动参数和开发版或体验版作为入口条件。满足条件时，欢迎页原按钮改为「进入蓝牙联调」，点击后进入独立普通页面。联调模式的欢迎页直接展示按钮，避免已绑定会话、后台登录回调或待处理 NFC 领取意图把测试人员带离。正式版的直接路由访问也须受环境限制。
- 常规启动保留现有欢迎页按钮、首页分流和 NFC 领取行为。联调页面复用项目导航组件，退出后返回欢迎页。扫描与连接状态、控制板信息、指令面板和通信记录均在同一独立页面内呈现。
- 联调页的视图和生命周期由页面管理，BLE 扫描、连接、协议收发和请求协调集中在本次联调的 BLE 会话中。应用层原有静默登录可以执行，BLE 会话无需等待登录或读取账号、宠物数据。

### 发现、握手与设备信息

- 测试人员主动扫描并手动选择设备。列表按扫描标识去重，显示可用的广播名和扫描标识，广播名缺失仍可选。设备是否兼容以实际 GATT 特征和协议握手为准。页面同一时刻只连接一块控制板，支持主动断开和重新扫描。
- 连接后发现 `FFF0` 服务、`FFF2` 写入特征与 `FFF1` 应答特征。按特征属性选择 Write 或 Write Without Response，以及 Notify 或 Indicate。先注册接收并订阅，订阅成功后等待约 200 毫秒，发送 `INFO`。确认 `PROTO=2` 和必需字段有效后发送 `STATUS`，收到可用状态后开放相应控制。
- `INFO` 校验和展示 `PROTO`、`FW`、`LEDS`、`SN`、`TYPE`。`SN` 是跨设备唯一的 24 位十六进制字符串，保留前导零。`TYPE=1` 显示锦鲤，`TYPE=2` 显示玉兔。`INFO` 无应答、格式有误或版本不符时，显示诊断并保持控制禁用。

### 指令、传输与错误处理

- 指令面板覆盖 `INFO`、`STATUS`、`LIGHT`、`HATCH` 和 `STOP`。灯光支持 `OFF` 及协议定义的 `SOLID`、`BLINK`、`BREATHE`、`ALTERNATE`、`CHASE`、`RAINBOW`、`FLOW`、`MARQUEE`。表单使用 V2.0 的范围和模式要求生成报文，包括 `RAINBOW` 的 RGB 固定值和 `SOLID` 的时长固定值。
- 原始输入接受以 `!` 开头、最多 128 字节的单行 ASCII 报文，自动补 `LF`。遵守协议的消息定界规则，保留输入的命令名与参数，允许未知命令和错误参数通过板端验证。原始输入和指令面板共用 BLE 收发及应答处理。
- 发送端对完整报文按最多 20 字节分包，逐包确认写入回调后继续，通常间隔约 30 毫秒。接收端有界缓存通知片段，支持单条拆分、多条合并、`LF` 和 `CRLF`，并按协议从新的 `!` 恢复。对其他设备或特征的通知予以忽略。
- 普通请求串行，按命令名匹配 `!OK` 与 `!ERR`。最后一个分包写入完成后进入 2 秒应答时限。页面区分蓝牙写入成功、板端受理、板端拒绝和操作结果未知，显示板端错误码和原始应答。
- `STOP` 可在普通请求写入或等待应答时优先发送。取消普通请求的剩余分包和待发操作，等正在写入的分包结束后立即发送完整 `STOP`。以 `STOP` 对应应答确认本次停止请求，迟到的普通请求应答保留在日志中。
- 写入失败、应答超时或应答格式错误时，标记结果未知，清除待发操作和未完成消息并断开。本轮通信记录可用于排查。测试人员重新选板连接后先核对 `INFO` 和 `STATUS`，动作指令只由测试人员主动触发。

### 破壳、前后台与记录

- 以 `STATUS` 的 `HATCH=FRESH`、`MOTOR=0` 和 `FAULT=0` 作为面板启用破壳的板端条件。出现未定义的 `HATCH` 值时禁止启动并保留原始应答。收到 `HATCH RUNNING` 后约每 500 毫秒查询 `STATUS`，直至离开 `RUNNING`。收到破壳错误应答后查询 `STATUS`。`DONE` 按协议表示定时动作结束，物理动作结果按真机验收确认。
- 切到后台暂停状态轮询。回到前台时，连接有效则重新查询 `STATUS`，板端仍为 `RUNNING` 时继续轮询。发生断开时显示离线，等待测试人员手动重新连接。退出页面时停止扫描、断开连接、清理计时器和监听。
- 记录附时间、收发方向、完整原始报文和结果。默认显示完整报文，按需展开写入分包和通知片段。支持复制和清空。记录仅保存在本次页面会话中，内容限于联调操作和 BLE 数据。

## 测试决定

- 以真实页面和 BLE 会话的行为为主要测试接入点，在微信 BLE API 边界模拟扫描、连接、写入回调、通知和断开。通过页面事件、可见状态、实际写出字节和调用顺序断言结果。沿用小程序现有 `Page` 和 `wx` 模拟方式，结合可控时钟覆盖延时、超时和轮询。
- 入口沿用欢迎页导航测试，覆盖开发版和体验版的显式入口、已有绑定会话、登录失败，以及常规启动的首页和 NFC 跳转。验证正式版无法进入联调模式。开发者工具验证实际页面注册和按钮绑定。
- 主链路验证扫描去重和手动选板、写入和订阅属性差异、握手顺序、版本不符、两种宠物原型、前导零序列号、分包、跨通知拼接及一条通知内多帧。
- 指令测试覆盖各灯光模式及参数边界、未知命令、板端拒绝、破壳运行和结束、`STOP` 抢占分包与迟到应答。超时、格式错误、断开和重连场景验证动作不会被自动补发。
- 页面生命周期测试覆盖切后台暂停、回前台查询、退出清理、记录复制和清空。后端停止时应能通过显式入口完成从扫描、连接到 BLE 收发的整条链路。
- 使用微信真机和支持 `PROTO=2` 的样板验收实际 BLE 收发。按板端协议第 9 节记录手机型号、固件版本、`SN`、`TYPE`、原始报文和动作前后 `STATUS`。灯光和破壳实际表现以样机观测为准。

## 不在范围内

- 联调业务接入后端、账号或设备绑定、NFC 领取、养成进度、产品破壳资格或产品页面的业务联动。
- 板端固件开发、机构标定、电机参数配置、破壳记录清除，以及旧协议兼容和自动探测。
- 自动选板、断线后自动重连或重发动作、越界报文注入、持久化或上传联调记录。

## 补充说明

- 指令字段、时序、状态和错误码以 [板端 BLE V2.0 通信协议](../../main/egg-miniprogram/docs/宠物蛋微信小程序与板端BLE简明通信协议_V2_0_2026-11-23.md) 为准。
- 协议记载现有 V5.0 固件使用 `PROTO=1`，V2.0 真机验收取决于可用的适配固件和样板。
