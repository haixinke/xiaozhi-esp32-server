模块采用「处理器-管理器-执行器」三层结构：
- `unified_tool_handler.py` 作为对外统一入口，负责初始化各执行器、处理LLM的function_call请求、合并多函数调用响应，并向上层暴露`handle_llm_function_call`等API。
- `unified_tool_manager.py` 中的`ToolManager`维护`Dict[ToolType, ToolExecutor]`注册表，缓存所有工具的`ToolDefinition`，按工具名查找对应`ToolType`后委派给具体执行器。
- `base/` 定义抽象基类`ToolExecutor`（`execute`/`get_tools`/`has_tool`）和类型枚举`ToolType`（SERVER_PLUGIN、SERVER_MCP、DEVICE_IOT、DEVICE_MCP、MCP_ENDPOINT），以及`ToolDefinition`数据类。
- 五个子包各自实现一种执行器：`server_plugins/plugin_executor.py`通过`plugins_func.register.all_function_registry`动态加载已注册插件；`device_iot/iot_executor.py`根据`conn.iot_descriptors`动态生成`get_devicename_property`和`devicename_method`两类工具；`server_mcp/`、`device_mcp/`、`mcp_endpoint/`分别封装服务端MCP客户端、设备端MCP协议及外部MCP Endpoint通信。
- 依赖方向单向向下：handler → manager → executor → base，各executor仅依赖base中的抽象类型，不互相耦合。
