# 小程序语音通话功能设计

**日期**: 2026-06-21  
**作者**: Claude Code  
**状态**: 已确认，待实现  
**关联项目**: 完美女友微信小程序 (`main/miniprogram/`)

---

## 1. 背景与目标

当前小程序已支持文字聊天和"按住说话"式语音输入。本设计新增一个**实时语音通话**功能，体验类似微信聊天中的语音通话：用户点击入口后进入全屏通话页，与 AI 女友进行持续双向语音交互，可随时挂断、静音、切换免提，或返回聊天页保持通话。

## 2. 设计决策摘要

| 决策项 | 结论 |
|---|---|
| 入口位置 | 聊天页输入框右侧 `+` 号 → 底部 3×2 浮窗 → "语音通话"卡片 |
| 实现方案 | 新增独立 `pages/voice-call` 页面，复用现有 `WebSocketManager` + `AudioManager` |
| 呼叫流程 | 点击后检查权益/权限 → 进入通话页 → "正在呼叫…" → 随机等待 2-8 秒 → 接通 |
| 通话控制 | 挂断、静音、免提/听筒切换、返回聊天页保持通话 |
| 默认音频输出 | 扬声器外放，可切换听筒 |
| 后台行为 | 切后台自动挂断 |
| 录音上限 | 单次录音 10 分钟无缝重启，通话继续 |
| 权益控制 | 新增 `voice_call` 权益，未订阅用户点击后引导订阅 |
| 状态可视化 | 简单文字提示："正在听…" / "女友正在说…" / "通话中" |

## 3. 方案对比与选择

### 方案 A：复用现有 WebSocket + AudioManager，新增独立通话页面（已选）

- **优点**：复用 Opus 编解码、WebSocket 心跳、设备认证；开发量最小；页面职责单一。
- **缺点**：若首页未连接，进入通话页前需要先"召唤"；通话与聊天共享后端会话。

### 方案 B：为通话新建独立 WebSocket 连接

- **优点**：通话与聊天完全解耦。
- **缺点**：需要维护两个连接；后端可能不支持同一设备多 session；开发成本高。

### 方案 C：在聊天页面内用全屏浮层实现通话

- **优点**：不需要新页面。
- **缺点**：聊天页与通话状态交织，代码复杂度高，不符合单职责原则。

**选择方案 A**，因为它在当前基础设施下实现成本最低，且边界清晰。

## 5. 状态机与数据流

### 通话状态机

```
idle ──点击语音通话──► calling ──2-8s 后──► connected ──挂断/后台/异常──► ended
```

| 状态 | UI 表现 | 音频行为 |
|---|---|---|
| `idle` | 无通话 | 无 |
| `calling` | 显示"正在呼叫…" + 头像 + 取消按钮 | 不录音、不播放 |
| `connected` | 显示通话时长、状态提示、控制按钮 | 开始录音并发送 Opus 帧；接收并播放服务端 Opus 帧 |
| `ending` | 显示"通话结束"过渡 | 停止录音和播放 |
| `ended` | 已离开页面 | 清理资源 |

### `voice-call-manager.js` 核心状态

```js
{
  state: 'idle' | 'calling' | 'connected' | 'ending' | 'ended',
  durationSeconds: 0,        // 通话时长（接通后开始计时）
  isMuted: false,            // 麦克风静音
  isSpeakerOn: true,         // 是否扬声器（默认 true）
  startTime: null,           // 接通时间戳
  callerTimer: null,         // 呼叫等待计时器
  durationTimer: null,       // 通话时长计时器
  pendingRoute: null,        // 记录从哪个页面进入（用于挂断后返回）
}
```

### 数据流

1. **发起通话**：首页点击 `+` 号 → 展示浮窗 → 点击"语音通话" → 检查 `voice_call` 权益 → 检查/申请麦克风权限 → 若首页 WebSocket 未连接则先"召唤" → `navigateTo` 到通话页。
2. **呼叫阶段**：`voice-call` 页面 `onLoad` 时设置 `state = calling`，启动 2-8 秒随机定时器。
3. **接通阶段**：定时器到期 → `state = connected` → 启动时长计时器 → 开始录音并发送 `listen start` → 接收 `audio` 帧播放。
4. **持续循环**：检测到服务端 `tts stop` 后，自动再次发送 `listen start`，进入下一轮倾听。
5. **静音切换**：`isMuted = true` 时停止录音但不发送 `abort`；恢复时重新 `startRecord()`。
6. **免提切换**：调用 `wx.setInnerAudioOption` 或相关 API 切换扬声器/听筒。
7. **返回聊天页保持通话**：`navigateBack` 回到首页，`voice-call-manager` 保持 `connected`，首页显示 `floating-call-ball`。
8. **挂断/后台/异常**：停止录音和播放，发送 `listen stop` / `abort`，`state = ended`，返回首页。

## 6. WebSocket 协议复用策略

### 复用现有基础设施

- **连接层**：复用 `WebSocketManager`，通过 URL query 传递 `device-id` 和 token。
- **音频层**：复用 `AudioManager` 的 24kHz PCM 录音 + Opus 编码，以及 Opus 解码 + WebAudio 播放。
- **消息协议**：复用现有的 `hello` / `listen` / `stt` / `llm` / `tts` / `audio` / `goodbye` 消息类型。

### 通话模式下的关键差异

当前聊天页是"一次触发 → 等待完整回复 → 回到 idle"。语音通话需要"持续监听、你说一句、AI 回一句、循环往复"。

| 步骤 | 客户端行为 | 服务端行为 |
|---|---|---|
| 接通 | 发送 `listen {mode:'manual', state:'start'}` | 开始接收音频并识别 |
| 用户说话 | 持续发送 Opus 音频帧 | ASR → STT → LLM → TTS |
| 服务端回复 | 接收 `tts start` / `audio` 帧 / `tts stop` | 输出语音 |
| AI 说完 | 检测到 `tts state === 'stop'` | 本轮结束 |
| 进入下一轮 | **自动再次发送 `listen start`** | 继续监听 |

### 如何区分"通话模式"与"聊天模式"

不需要新增服务端协议字段，区分逻辑在客户端：

- 通话页面处于 `connected` 状态时，AI 回复结束后自动重新 `sendListenStart()`。
- 聊天页面保持现有行为：用户主动触发一次对话，回复结束后回到 `idle`。

### 10 分钟录音重启

微信小程序 `RecorderManager.start({ duration: 600000 })` 单次录音上限为 10 分钟。到达后：

1. 发送 `listen stop`
2. 立即重新 `audioManager.startRecord()`
3. 立即重新 `sendListenStart()`

用户侧无感知，通话继续。

## 7. UI 交互细节

### 首页底部多功能浮窗

- 触发：输入框右侧 `+` 号按钮点击
- 位置：从底部弹出，覆盖输入栏
- 布局：3×2 网格，目前只有"语音通话"一个卡片，其余 5 格留白
- 卡片：图标 + 文字"语音通话"
- 关闭：点击浮窗外区域或再次点击 `+` 号

### 语音通话页面

**呼叫阶段（calling）**

- 全屏显示女友头像（圆形，居中）
- 头像下方文字："正在呼叫…"
- 底部一个"取消"按钮（灰色）
- 2-8 秒后自动切换到通话阶段

**通话阶段（connected）**

- 顶部：女友头像 + 名字 + 通话时长 `00:32`
- 中部状态文字：
  - "正在听…"（用户说话时）
  - "女友正在说…"（AI 播放时）
  - "通话中"（双方都安静时）
- 底部控制区：
  - 静音按钮（麦克风开/关）
  - 免提按钮（扬声器/听筒切换）
  - 挂断按钮（红色大圆按钮）
- 右下角小按钮："返回聊天"（回到首页，通话保持）

### 悬浮通话小球

- 位置：屏幕右侧居中偏下
- 显示：通话时长 + 迷你挂断图标
- 点击：展开小面板（"返回通话" / "挂断"）
- 深色模式：通过 `darkMode` 属性切换

### 深色模式

- 通话页根容器 `class="container {{darkMode ? 'dark' : ''}}"`
- 深色下背景 `#121220`，文字 `#e8e4e3`
- 控制按钮使用玻璃态效果，符合现有设计系统

## 8. 错误处理与边界情况

### 权限相关

| 场景 | 行为 |
|---|---|
| 首次点击语音通话 | 调用 `wx.authorize({ scope: 'scope.record' })` |
| 用户同意 | 进入通话页 |
| 用户拒绝 | 弹出引导框，提示需要麦克风权限，提供"去设置"按钮 |
| 通话中用户去设置关闭权限 | 下次返回小程序时检测到无权限，自动挂断 |

### 网络与连接

| 场景 | 行为 |
|---|---|
| 进入通话页时 WebSocket 未连接 | 先自动调用首页的"召唤"逻辑建立连接，再进入 calling 状态 |
| 通话中 WebSocket 断开 | 立即显示"连接已断开"并自动挂断，返回首页 |
| 通话中音频引擎报错 | 显示"音频异常，通话已结束"，自动挂断 |
| 切后台 | 自动挂断 |

### 状态竞争

| 场景 | 行为 |
|---|---|
| 用户在 AI 说话时挂断 | 立即停止录音和播放，发送 `abort`，忽略后续 `audio` 帧 |
| 用户快速多次点击挂断 | 防抖处理，第一次生效后禁用按钮 |
| 录音 10 分钟到期 | 自动 `listen stop` → 重启录音 → `listen start`，UI 不提示 |
| 用户从通话页返回首页又立刻再进入 | 复用同一通话状态，不重新触发呼叫等待 |

### 权益控制

- 未订阅 `voice_call` 权益的用户点击语音通话卡片：
  - 显示引导弹窗："签订契约后即可与女友语音通话"
  - 提供"去订阅"和"知道了"按钮
  - 不进入通话页
