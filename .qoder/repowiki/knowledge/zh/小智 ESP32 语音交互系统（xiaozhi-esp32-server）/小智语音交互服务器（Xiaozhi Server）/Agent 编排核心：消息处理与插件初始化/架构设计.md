本模块由 `core/handle`（消息处理层）和 `core/utils`（插件工具层）两部分协作完成 Agent 编排：
- 消息流入口：`textMessageHandlerRegistry.TextMessageHandlerRegistry` 在启动时集中注册 hello/abort/listen/iot/mcp/server/ping 七类处理器，`textMessageType.TextMessageType` 提供统一枚举；`textMessageProcessor` 负责解析 JSON 消息并按类型查表分发。
- 音频流入口：`receiveAudioHandle`、`sendAudioHandle`、`reportHandle` 等独立处理器直接调用 utils 中的 ASR/TTS/VAD 实例。
- 插件装配：`modules_initialize.initialize_modules` 根据配置字典中的 `selected_module` 字段，通过各子模块的 `create_instance` 工厂方法按需创建 TTS/LLM/Intent/Memory/VAD/ASR 实例，并以字典形式返回供上层注入。
- 共享能力：utils 下的 `context_provider`、`prompt_manager`、`cache`、`dialogue`、`memory`、`voiceprint_provider`、`wakeup_word` 等被所有处理器共同消费，形成跨消息/音频路径的上下文与状态共享。
- 隔离机制：每个消息类型对应独立的 Handler 类，新增类型只需实现基类并注册到 Registry，不改动现有代码；插件之间通过统一的 create_instance 接口解耦。
