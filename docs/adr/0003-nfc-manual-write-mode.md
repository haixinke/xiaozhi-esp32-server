# 0003. NFC 手动写卡模式：触碰自验证 + 锁卡前移到入库门禁

- 状态：已接受
- 日期：2026-08-27

## 背景

NFC 蛋宝宝处于小批量验证阶段（每批几十张），没有专业批量写卡设备，写卡靠手机 NFC App（如 NFC Tools）逐张写入。既有工厂 CSV 通道（写卡 CSV 导出 → 工厂设备写入 → 结果 CSV 导入）的硬校验由工厂设备能力决定：完全成功必须 `is_read_only=true`、`uri_sha256` 匹配、`ndef_record_count=2`（见 `PdcNfcWriteResultImporterImpl`）。手机写卡无法产出这些证据：锁卡后无法回读计算 sha256 供导入，且锁死即不可返工，与验证阶段"写错重写"的需求冲突。

同时这批卡会发给真实用户，完全不锁卡意味着市面流通可改写标签，任何人可用 NFC App 把 `openlink` 指向钓鱼页。

## 决策

1. **写卡任务创建时二选一模式**：工厂 CSV 模式 / 手动模式，互斥，任务内不混用。手动模式不使用 CSV 导入通道，改走单资产粒度接口（列表、单条解密 scheme、逐张标记）。

2. **手动模式以触碰自验证替代文件证据**：资产被标记"已写入"（`WRITTEN`）后，用手机真实触碰标签，微信拉起领取页调 `preview(claimRef)`；preview 命中即证明 URI 写对、openlink 有效、微信能打开页，后端自动推进 `WRITTEN → VERIFIED`（记 `verify_source=TOUCH`）。只对"已标记已写入且在手动任务中"的资产生效，野生触碰不动状态。人工确认（NFC Tools 回读比对后点"验证通过"，记 `verify_source=MANUAL`）作为兜底。手动模式豁免 `uri_sha256` / `ndef_record_count` / 写入时 `is_read_only` 的硬校验。

3. **锁卡从写入环节前移到入库门禁**：手动模式写入时不锁卡（保留写坏回 `SCHEME_GENERATED` 重试的能力）；顺序硬性为 `VERIFIED` → 人工锁卡并确认 → 锁后触碰复验仍可读 → 允许 `VERIFIED → IN_STOCK`。手动模式资产入库强制 `is_read_only=true`，未锁拒绝入库。锁卡按钮在 `VERIFIED` 前禁用，点击二次确认不可逆。工厂 CSV 通道的写入时锁卡校验不变。

## 否决的替代方案

- **手机写卡也走 CSV 导入**：手机流程产不出导入器要求的 sha256 与锁卡证据，且逐张填 14 列 CSV 比逐张点选更繁。
- **写入时即锁卡**：验证阶段写错率高，锁死即废卡，返工成本不可接受。
- **完全不锁卡**：卡发真实用户，可被任意改写指向钓鱼页，安全风险不接受。

## 后果

- 触碰自验证依赖 preview 接口能识别"手动任务中的 WRITTEN 资产"，需在 claim 链路加一个无副作用的状态推进分支；该分支只进状态不核销。
- 同一物理卡锁过后写错无法重写，只能报废（`SCRAPPED`）补新资产；锁前触碰验证 + 锁后触碰复验把废卡拦在操作员手里。
- iPhone 写卡无法写标准 AAR 记录（仅 Android 使用），接受该缺口：URI Record 双端通用，AAR 仅 Android 辅助定位。
- 量产回归工厂 CSV 通道时本模式不移除，二者按任务粒度并存。
