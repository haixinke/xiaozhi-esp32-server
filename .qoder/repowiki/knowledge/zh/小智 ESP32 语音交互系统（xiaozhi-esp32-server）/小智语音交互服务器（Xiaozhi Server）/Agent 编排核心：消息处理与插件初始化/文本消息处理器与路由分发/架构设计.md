采用"处理器抽象 + 注册表 + 处理器"三层结构：
- `textMessageHandler.py` 定义抽象基类 `TextMessageHandler`，要求子类实现 `handle(conn, msg_json)` 和 `message_type` 属性。
- `textMessageType.py` 通过 `TextMessageType` 枚举集中声明支持的七种消息类型（HELLO/ABORT/LISTEN/IOT/MCP/SERVER/PING）。
- `textMessageHandlerRegistry.py` 的 `TextMessageHandlerRegistry` 在构造时自动注册所有内置处理器，提供 `register_handler` / `get_handler` / `get_supported_types` 接口。
- `textMessageProcessor.py` 的 `TextMessageProcessor` 是统一入口，负责 JSON 解析、日志记录、按 `type` 字段查表并调用对应 handler。
- `textHandle.py` 暴露全局 `message_registry` 与 `message_processor` 单例，对外仅暴露 `handleTextMessage(conn, message)` 协程。
- `textHandler/` 子目录每个文件对应一种消息类型的具体处理器，内部再委托给 `core.handle` 下的业务处理函数（如 `helloHandle.handleHelloMessage`、`abortHandle.handleAbortMessage`），保持职责单一。
- 依赖方向单向：processor → registry → handler → 业务 handle 函数，handler 之间互不依赖。
