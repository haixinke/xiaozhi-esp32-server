# 04: 删除小物件（软删语义验证）

**What to build:** 运营在列表操作列点"删除"，二次确认后记录从列表消失，详情接口返回"物件不存在"。数据仍保留在库中（软删），但列表与详情一律按"已删除 = 不存在"处理，不提供回收站与恢复入口。关键验证：删掉某类型的物件后，可以再为同一类型新建物件——即软删不会因为数据库唯一索引而阻挠重建。

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] 删除接口把删除标记置位，不物理删除行
- [ ] 删除接口对不存在或已删除的 id 返回"物件不存在"，不做幂等成功
- [ ] 列表与详情都过滤已删除记录（过滤点共三处：分页、详情、唯一性校验），不引入框架级全局逻辑删除注解（与仓库既有约定及 ADR 0006 一致）
- [ ] 列表操作列出现"删除"按钮，二次确认后调用删除接口并刷新列表
- [ ] Service 集成测试：删除后详情报"物件不存在"、删除后分页不再返回该记录、删除同一类型后可再建同类型物件、重复删除同一 id 报"物件不存在"
- [ ] 测试清理阶段物理清除本用例产生的行（含已软删的行），避免 dev 库累积
