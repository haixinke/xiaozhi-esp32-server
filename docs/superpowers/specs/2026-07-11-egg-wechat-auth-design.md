# 蛋宝宝微信注册与授权登录设计

## 目标

让蛋宝宝微信小程序通过现有 `manager-api` 完成真实的微信注册和登录，获得并维护 Bearer Token，替代当前仅调用 `wx.login`、再将微信资料写入本地 Mock 的伪登录流程。

本次只接入认证闭环，不改造宠物业务数据接口，不新增或修改后端端点，也不补充后端登录服务测试。

## 已确认的产品约束

- 小程序启动后立即通过 `wx.login` 静默注册或恢复登录态，但新用户和未绑定手机号的历史用户必须停留在欢迎页，不能仅凭 `userId` 进入首页。
- 首次进入不获取微信昵称或头像；默认展示身份为“蛋友”，用户后续可在“我的 → 个人信息”自行填写昵称和头像。
- 手机号是使用小程序的强制门槛。用户勾选隐私政策并主动点击授权按钮后，通过微信 `getPhoneNumber` 获取动态 code；拒绝授权或绑定失败时不得进入首页。
- 已绑定手机号的返回用户可在静默登录返回 `hasPhone=true` 后直接进入首页，无需重复授权。
- 应用级路由守卫必须覆盖分享、二维码和场景值直接启动的非欢迎页面；任何 `hasPhone!==true` 的会话都重启导航到欢迎页，不能只依赖欢迎页自身判断。
- 正常入口必须获得有效的服务端登录态。后端不可用或登录失败时停留在欢迎页并允许重试，不降级成本地 Mock 登录。
- 现有展会快速体验可继续作为独立的本地演示能力。
- 退出登录时清除认证信息和账号相关的本地宠物、展会备份数据，避免同一设备切换微信账号后的数据串用；非账号界面偏好可保留。

## 方案选择

采用姊妹小程序的成熟认证模式，但为蛋宝宝重新划定安全边界：认证存储、HTTP 请求和登录协调分别封装，支持登录态恢复、提前续期、401 单次重试与并发登录锁。

不采用以下方案：

- 只在欢迎页调用一次 `/wechat/login`：缺少统一鉴权、续期和重试，后续接宠物接口时必然返工。
- 同时全面重构后端认证：范围过大。已发现的后端账号安全、并发首次注册、限流和 session key 存储问题应作为独立加固任务处理。

## 现有后端契约

小程序调用：

```text
POST /xiaozhi/wechat/login
Content-Type: application/json

{ "code": "<wx.login code>" }
```

该端点匿名可访问。后端用 code 调用微信 `jscode2session`，已有微信映射时登录已有用户，没有映射时自动创建 `sys_user` 与 `ai_wechat_user`，然后签发 token。

响应使用统一信封：

```text
{
  "code": 0,
  "msg": "success",
  "data": {
    "token": "...",
    "expire": 43200,
    "openid": "...",
    "userId": 123,
    "isNewUser": true,
    "hasPhone": false,
    "agentId": null
  }
}
```

`userId` 是蛋宝宝业务账号主键。`openid` 仅用于微信身份映射，不得用作宠物 ID、设备 ID 或鉴权依据。客户端传入的身份字段也不得替代服务端 token 鉴权。

## 客户端组件与职责

### 认证存储 `utils/auth.js`

该模块只负责认证数据，不发网络请求。它保存和读取：

- `token`
- `userId`
- `openid`
- `isNewUser`
- `hasPhone`
- token 签发时间
- token 有效期（秒）

它提供保存、恢复、清除和临期判断能力。token 在到期前 5 分钟视为临期，以吸收客户端时钟漂移和请求耗时。缺少 token、签发时间、有效期或 `userId` 的记录均视为无效登录态。

### HTTP 请求 `utils/request.js`

该模块集中管理 `manager-api` 基础地址、统一信封解析和请求错误。调用者必须显式声明请求是否匿名，不能通过 URL 包含 `login` 等模糊规则推断。

鉴权请求自动添加 `Authorization: Bearer <token>`。HTTP 2xx 但业务 `code !== 0` 仍是失败。成功响应只向调用者返回 `data`，错误对象提供稳定的错误类型、业务错误码和可安全展示的用户提示。

鉴权请求收到 HTTP 401 时：

1. 清除失效认证态。
2. 调用 `App.silentLogin()`。
3. 登录成功后只重试原请求一次。
4. 重试仍失败则返回错误，不再递归重试。

### 登录协调器 `app.js`

`app.js` 维护全局认证状态和单例登录 Promise。`silentLogin()` 的数据流为：

```text
wx.login
  -> 获取一次性 code
  -> POST /wechat/login（匿名）
  -> 校验 token、expire、userId 等必需字段
  -> 写入 auth storage 和 globalData
  -> 登录就绪
```

多个页面或请求同时触发登录时复用同一个 Promise，避免重复调用 `wx.login` 和后端登录端点。Promise 无论成功或失败都必须释放单例锁，使用户可以重试。

启动时优先恢复未临期的本地登录态；缺失或临期则执行静默登录。小程序回到前台时，已有 token 若进入提前 5 分钟窗口则刷新。网络刷新失败时，尚未真正过期的 token 可继续使用；已过期 token 必须清除。

### 欢迎页 `pages/welcome`

欢迎页负责：

- 隐私政策勾选。
- 等待启动阶段的静默登录，并在必要时触发 `App.ensureLogin()` 重试。
- 仅当登录响应 `hasPhone=true` 时自动进入首页；只有 `userId` 不得跳转。
- 使用 `button open-type="getPhoneNumber"` 接收 `e.detail.code`，调用受认证保护的 `POST /wechat/bindPhone`。
- 隐私政策未勾选、用户拒绝手机号、动态 code 缺失或绑定接口失败时均停留在欢迎页并允许重试。
- 手机号绑定成功后更新本地 session 和 `globalData.hasPhone`，用后端 `userId` 写入默认展示用户，再进入首页。

欢迎页不再调用 `wx.getUserProfile`，也不再以 `petStore.getUser()` 作为真实登录判据。后端登录失败时不得创建本地用户或进入首页。

### 退出登录 `pages/account`

退出动作统一调用 App 的退出方法，清除：

- auth storage 中的全部认证字段。
- `globalData` 中的认证字段。
- 当前本地展示用户。
- 账号相关的宠物 Mock、任务状态、收藏卡和展会备份。

完成后重定向欢迎页。退出不调用不存在的服务端注销端点。

## 配置

后端基础地址放在单独配置模块，由 `request.js` 引用，不在页面和业务模块中重复硬编码。本地联调可指向当前机器的 `http://<LAN-IP>:8002/xiaozhi`；真机和生产必须使用已加入微信 request 合法域名的 HTTPS 地址。

小程序代码和日志中不得出现微信 AppSecret 或其他服务端密钥。后端 AppID 必须与蛋宝宝小程序 AppID 对应，AppSecret 只通过后端环境变量配置。

## 错误处理与用户体验

- 未同意隐私政策：静默注册可以已经完成，但不得发起手机号绑定或进入首页，提示先阅读并同意。
- `wx.login` 失败：停留欢迎页，提示“微信登录失败，请重试”。
- 网络或后端不可用：停留欢迎页，提示“暂时无法连接服务，请稍后重试”。
- 业务响应失败或字段不完整：视为登录失败，不写入部分认证状态。
- token 过期：鉴权请求自动尝试一次重新登录和重试。
- 连续失败：停止自动重试，将控制权交还页面和用户。
- 用户拒绝手机号授权：停留欢迎页，提示“需要授权手机号后才能使用蛋宝宝”。
- 手机号绑定失败：保留现有登录态，停留欢迎页并允许重新授权。

内部错误详情可用于开发期定位，但任何对用户的消息和日志都不得包含微信 code、token、openid、Authorization、完整登录响应、密码或 AppSecret。

## 测试与验证

蛋宝宝小程序没有包管理器，新增测试使用 Node 内置能力和轻量微信 API Mock，不引入生产依赖。测试覆盖：

- 有效 token 恢复以及到期前 5 分钟的临期判断。
- 登录响应校验和认证态原子保存。
- 并发登录只调用一次 `wx.login`。
- `wx.login`、网络、业务错误与响应缺字段均不会形成登录态。
- HTTP 401 只刷新并重试一次。
- 欢迎页只在 `hasPhone=true` 时自动进入首页，未绑定用户不能凭 `userId` 跳过欢迎页。
- 未勾选隐私协议时不调用手机号绑定接口。
- 手机号动态 code 缺失、用户拒绝、接口失败时不进入首页。
- 手机号绑定成功后持久化 `hasPhone=true` 并进入首页。
- 退出后认证数据和账号相关 Mock 数据均被清除。

同时运行现有验证：

```bash
node main/egg-miniprogram/scripts/verify-project.js
find main/egg-miniprogram -type f -name '*.js' -print0 | xargs -0 -n1 node --check
find main/egg-miniprogram -type f -name '*.json' -print0 | xargs -0 -n1 jq empty
```

最终还需在微信开发者工具和真机验证真实 `wx.login`、合法域名、后端 AppID 匹配、token 续期、网络失败重试与退出后重新登录。

## 非目标与后续工作

本次不包含：

- 微信昵称和头像授权；用户后续在个人信息页自行维护。
- 宠物 adopt、孵化任务、破壳等业务接口接入。
- 服务端退出或 token 主动吊销。
- 后端微信登录测试。
- 后端认证安全加固。

手机号门槛在欢迎页完成。后续业务统一依赖服务端登录响应中的 `hasPhone`，不得仅凭客户端本地标记绕过门槛。
