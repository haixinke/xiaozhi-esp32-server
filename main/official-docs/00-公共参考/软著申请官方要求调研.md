# 计算机软件著作权登记官方要求调研报告

## 1. 调研范围与来源说明

本报告以**一手官方来源**为主：

- 中国版权保护中心官网（`www.ccopyright.com.cn`）软件著作权登记指南，包括《申请须知》《办理步骤》《所需文件》《填表说明》《问题问答》等栏目；
- 国家版权局《计算机软件著作权登记办法》（国家版权局令第 1 号）；
- 财政部、国家发展改革委《关于清理规范一批行政事业性收费有关政策的通知》（财税〔2017〕20 号）；
- 中国版权保护中心《关于停征软件著作权登记缴费有关事项的通告》（中版权字〔2017〕33 号）。

对于官方未作明确说明的事项（如命名禁用词清单、多模块登记口径、常见补正原因分类），补充引用**二手来源**（代理机构、法律服务平台、行业文章）并明确标注。

## 2. 申请流程

当前（2025-2026 年）计算机软件著作权登记**全程在线办理**，无需现场或邮寄纸质原件（除特定继受登记需寄回证书原件外）。官方流程为：

> 账号注册 → 实名认证 → 填报提交 → 登记机构受理 → 登记机构审查 → 取得登记证书[^2^]

关键节点：

- **账号注册与实名认证**：在中国版权保护中心官网注册后，办理登记业务前须完成实名认证[^2^]。
- **在线填报与上传**：选择“R11 计算机软件著作权登记申请”，在线填写并上传申请材料。上传文件须为 **PDF 格式**；照片需清晰、平铺、无反光、无遮挡[^1^]。
- **申请确认签章页**：在线打印申请确认签章页，签章后上传扫描件（PDF），不得擅自更改内容、格式或打印比例[^1^][^3^]。
- **受理**：材料符合受理要求的，发放受理通知书；缺少签章页或鉴别材料的，不予受理[^2^]。
- **审查与补正**：自受理日起 **60 日内**审查完成；材料存在缺陷的，发送补正通知书，申请人须在 **30 日内**补正，逾期视为撤回[^2^][^6^]。
- **发证与公告**：审核通过后，申请人可在用户中心下载**软件版权登记电子证书**（PDF，带电子签章），并可在官网查阅登记公告[^1^][^2^]。
- **费用**：自 2017 年 4 月 1 日起，软件著作权登记费（含申请费、证书费、合同登记费、变更/补充登记费、封存保管费、查询费等）已**停征/取消**，自行申请无官费[^7^][^8^]。

## 3. 所需材料清单

根据《计算机软件著作权登记办法》第九条、第十一条及中国版权保护中心《所需文件》栏目，企业申请需准备：

| 材料 | 说明 |
|------|------|
| 软件著作权登记申请表 | 在线填写，打印签章页并签章后上传 PDF[^3^] |
| 软件鉴别材料 | 源程序 + 任一种文档（用户手册/操作手册/设计说明书等）[^3^][^6^] |
| 身份证明 | 企业法人：加载统一社会信用代码的营业执照副本扫描件[^3^] |
| 权利归属证明文件 | 合作开发合同、委托开发合同、任务书、原著作权人许可证明、转让/继承证明等（视开发/取得方式而定）[^3^][^6^] |
| 申请确认签章页 | 在线打印、签章、上传 PDF[^1^] |

**企业申请与个人申请差异**：企业提交营业执照副本；自然人提交身份证；外国主体需护照或经认证/附加证明书的身份证明及中文译本[^3^]。

## 4. 源代码格式要求

官方依据为《计算机软件著作权登记办法》第十条及中国版权保护中心《所需文件》：

- **页数**：提交源程序的**前 30 页和后 30 页**，共 60 页；整个源程序不足 60 页的，**应当提交全部源程序**[^6^][^3^]。
- **行数**：程序每页**不少于 50 行**[^6^][^3^]。
- **连续性**：前后代码必须连续，不得人为插入空行、重复代码或大量注释凑页数。
- **页眉页脚**：每页页眉须标注**软件全称 + 版本号**，内容应与申请表一致；右上角标注连续页码[^5^][^3^]。
- **格式**：PDF 文件，A4 纸张，纵向排版，文字从左向右排列[^1^][^3^]。
- **例外交存**：如源程序含有商业秘密，可按《登记办法》第十二条规定的方式之一作例外交存[^6^]。

## 5. 文档格式要求

- **文档类型**：可提交**用户手册、操作手册、设计说明书**等中的任一种[^3^][^6^]。
- **页数**：与源代码相同，提交文档的**前 30 页和后 30 页**；不足 60 页的，提交全部文档[^6^][^3^]。
- **行数**：文档每页**不少于 30 行**；以图片、界面截图为主的页面可适当放宽[^6^][^5^]。
- **页眉页脚**：页眉标注**软件全称 + 版本号**，与申请表一致；页码连续；封面一般不加页眉[^5^][^3^]。
- **内容**：应图文并茂，说明软件功能特点、运行环境、操作方法或技术架构，与申请表、源代码保持一致[^3^]。
- **版本号标注**：鉴别材料页眉的软件版本号应与申请表一致，但“有无 V”以申请表填报为准[^3^]。

**官方未见对文档最低页数的明确规定**。实务中代理机构常建议至少 10–15 页，但官方核心关注点是内容完整、清晰、与申请表一致。

## 6. 软件全称/简称/版本号命名规范

依据中国版权保护中心《填表说明》[^4^]及《问题问答》[^5^]：

- **软件全称**：申请登记的软件的完整名称，应“简短明确、针对性强”，申请材料中全称须保持一致。
- **软件简称**：对全称进行简化的名称；没有简称请留空，不要填写“无”，也不要与全称完全相同[^4^]。
- **版本号**：建议按规范填写，如 **V1.0** 或 **1.0**；登记证书中的版本号以申请表填报为准[^4^]。
- **重名**：官方 Q&A 明确，只要是独立开发享有著作权的软件都可以申请登记，一般情况下软件名称可以相同或相似[^5^]。

**官方未见明确的“禁用词清单”**。根据二手来源的通行做法/代理经验，应避免：国家机关/事业单位名称、夸大敏感词（如“中国”“全国”“唯一”“万能”等）、他人商标/品牌、纯英文全称、特殊符号、尾缀混用（如“系统”“平台”“软件”不规范叠加）等[^9^]。

## 7. 关键填写项

依据中国版权保护中心《填表说明》[^4^]：

- **开发完成日期**：填写开发完成并固定在有形载体（如硬盘、光盘）上的日期。
- **首次发表日期**：填写著作权人首次将该软件公之于众的日期，方式包括销售、网上发布、产品发布、为销售目的的展示等；**未发表的选择“未发表”**。
- **开发方式**：
  - 单独开发：依靠自身条件自行开发完成；
  - 合作开发：两人以上依据合作协议共同开发，需提交合作开发合同；
  - 委托开发：依据委托协议开发，需提交委托开发合同；
  - 下达任务开发：依据国家机关下达的项目任务书开发，需提交任务书或合同。
- **权利取得方式**：原始取得或继受取得（受让、继承、承受）。原始取得要求软件为独立开发；继受取得需提交相应证明文件[^4^]。
- **权利范围**：可选择“全部权利”（《计算机软件保护条例》第八条规定的所有权利）或“部分权利”并具体列明[^4^]。

## 8. 开源代码衍生软件的登记

### 8.1 官方规则

《计算机软件著作权登记办法》第七条规定：

> 申请登记的软件应是独立开发的，或者**经原著作权人许可对原有软件修改后形成的在功能或者性能方面有重要改进的软件**[^6^]。

第十一条第（三）项规定：

> 经原软件著作权人许可，在原有软件上开发的软件，应当提交**原著作权人的许可证明**[^6^]。

### 8.2 MIT 协议下的二次开发

- MIT 属于**宽松型（Permissive）开源许可证**，允许自由使用、修改、合并、发布、分发、再许可、销售，且**无传染性条款**，不要求衍生作品继续开源[^10^]。
- 基于 MIT 代码二次开发，开发者对**新增或修改的独创性表达部分**可以享有著作权；软件著作权登记保护的是程序及其文档的**表达形式**，不延及思想、算法、技术方案[^5^][^11^]。
- 登记时并不审查申请人采用何种开源协议，但基于 MIT 代码的二次开发作品申请登记时，应保留上游 MIT LICENSE 文件，作为“原著作权人许可证明”[^6^][^11^]。
- 登记的权利范围**仅及于申请人享有著作权的独创性部分**，不及于原 MIT 代码部分；对外分发时仍需遵守 MIT 协议关于保留版权声明和许可声明的义务[^10^][^11^]。

**结论**：MIT 协议下二次开发成果可以申请软件著作权登记，但应在材料中说明/提交上游许可，并明确登记保护的是自身独创性表达。

## 9. 审查时长与补正

- **审查周期**：自受理日起 **60 日内**完成审查[^6^][^2^]。
- **补正期限**：自发出补正通知之日起 **30 日内**补正，逾期未补正视为撤回申请[^6^][^2^]。
- **发证时间**：审核通过后，电子证书可在用户中心下载[^1^]。

**常见补正原因**：官方未发布统一“常见补正原因清单”，但根据二手来源的实务总结，高频退回原因包括[^12^]：

1. 申请材料缺失：签章页未签章、未上传正确签章页、缺少鉴别材料等；
2. 软件名称不规范：含敏感/夸大词、尾缀不规范、与申请表不一致等；
3. 材料之间不一致：源代码、文档、申请表中的软件名称、版本号、功能描述不一致；
4. 权利归属证明不足：合作/委托开发缺少合同，或合同软件名称与申请名称不一致；
5. 源代码或文档格式不符：页数/行数不够、页眉页脚缺失、非 PDF 等；
6. 源代码与他人已登记软件实质性相似或独创性不足。

## 10. 自行申请 vs 代理机构

- **官方渠道**：中国版权保护中心官网 `https://www.ccopyright.com.cn`，在线登记系统 `https://register.ccopyright.com.cn`[^1^][^2^]。
- **官费**：自 2017 年 4 月 1 日起，软件著作权登记及相关业务**不再收取行政事业性官费**，自行申请成本为 0[^7^][^8^]。
- **代理机构**：仅产生代理服务费，无统一官费。市场行情中，普通代理服务费数百至数千元不等，加急服务更贵；本报告不做具体推荐。

## 11. 多模块/多子系统软件登记

**官方未见针对“前端 + 后端”必须合并或分开登记的明确规定**。

通行做法：

- 若前后端共同构成一个完整软件产品、功能不可分割，通常作为**一个软件著作权**登记；
- 若前后端可独立运行、独立构成完整产品，可分别登记为不同软件著作权。

对于一个 Web 管理控制台（Vue.js 前端 + Java Spring Boot 后端），由于前端通常依赖后端 API 才能完整运行，实务中多按**一个软件**合并登记。

## 12. 对本案（智控台软著申请）的直接影响

结合本案背景：上海爱予慧科技有限责任公司拟基于“智控台”（Vue.js 2 Web 管理控制台 + Java Spring Boot 后端）申请软件著作权，且该项目 fork 自 MIT 协议开源项目 `xiaozhi-esp32-server`（原作者 xinnan-tech）。

| 调研结论 | 对本案的影响 |
|----------|--------------|
| **企业申请** | 著作权人为上海爱予慧科技有限责任公司，需提交加载统一社会信用代码的营业执照副本扫描件[^3^]。 |
| **MIT fork** | 项目基于 MIT 协议开源代码二次开发，申请时应保留上游 `LICENSE` 文件作为原著作权人许可证明，并在材料中说明基于 MIT 代码的改进情况；登记权利范围仅覆盖本公司的独创性表达部分（如智控台前端界面、业务逻辑、管理功能等），不及于原开源代码[^6^][^10^][^11^]。 |
| **软件名称** | 建议拟定为规范形式，例如“**爱予慧智控台软件 V1.0**”。避免使用“中国”“全国”等敏感夸大词，避免纯英文全称，确保申请材料中全称、版本号完全一致[^4^][^9^]。 |
| **前后端结构** | 智控台前、后端通常视为同一系统组成部分，建议**合并登记一个软著**。源代码可将前端与后端代码合并整理，提交前 30 页 + 后 30 页（共 60 页），每页不少于 50 行；若总代码不足 60 页则全部提交。 |
| **文档** | 提交用户手册或操作手册，前 30 页 + 后 30 页（不足 60 页全部提交），每页不少于 30 行；页眉标注“爱予慧智控台软件 V1.0”，右上角连续页码；内容应覆盖功能模块、操作环境、使用流程[^3^][^5^]。 |
| **关键填写项** | 开发完成日期按实际完成时间填写；若未对外发布，首次发表选择“未发表”；开发方式如为公司独立开发则选“单独开发”；权利取得方式选“原始取得”；权利范围选“全部权利”[^4^]。 |
| **费用** | 自行在中国版权保护中心官网申请无官费；如需加急或委托代理，仅产生服务费[^7^][^8^]。 |
| **补正风险** | 重点防范：申请表/源代码/文档三者软件名称或版本号不一致；源代码行数不足或页眉缺失；文档内容未体现软件功能；未保留 MIT 授权文件导致权属说明不完整[^12^]。 |

**下一步建议**：

1. 确认“智控台”是否已对外发布，确定首次发表日期或选择“未发表”。
2. 整理前后端源代码，确保总页数或 60 页片段满足每页 ≥50 行，页眉统一。
3. 编写/修订用户手册，确保与申请表功能描述一致，页眉统一。
4. 保留上游 `xiaozhi-esp32-server` 的 MIT LICENSE 文件，作为许可证明材料。
5. 如不确定名称合规性，可在中国版权保护中心登记系统进行名称查重或咨询官方客服热线 010-61090099。
