# 02: 新增小物件（类型下拉 + 图片上传 + 故事）

**What to build:** 运营点"新增小物件"打开弹窗，类型下拉只列出尚未被任何未删除物件占用的字典小类；运营上传一张 png/jpeg/webp（2MB 内）图片并看到预览，填写最长 2000 字的故事（带字数统计），保存后弹窗关闭、列表出现新记录。若类型已被占用、类型不在字典中、图片缺失、故事为空或超长，保存被拒绝并给出准确提示。图片上传走独立的 `small-object` 场景，OSS 路径与游戏图标、涂鸦作品隔离。本片只实现新增；编辑已有物件的回填与改类型由后续票实现。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 上传场景枚举追加 `small-object`：允许 png/jpeg/webp，单文件上限 2MB，**不允许 svg**（不复用游戏图标场景，既有扩展名映射也不支持 svg，复用会产出缺扩展名的 OSS key）
- [ ] 新增"可选物件类型"接口，返回每个字典小类的 key、显示名、是否已被占用；占用判断由后端统计未删除记录得出（前端分页视角看不到跨页占用）
- [ ] 新增保存接口与服务端校验：类型必须在 `SMALL_OBJECT_TYPE` 字典中存在、同一类型在未删除记录中只允许一条、图片非空、故事非空且长度不超过 2000
- [ ] 错误码新增"物件类型不存在"与"该类型已被占用"两项（"物件不存在"已由 01 引入），并同步到全部七套 messages 文案（含 `messages.properties` 基包）；DTO 校验文案同步到全部七套 validation 文案
- [ ] 弹窗内类型下拉数据来源是"可选物件类型"接口，不是字典全量列表（字典中混有固件类型、手机区号等非物件类型）
- [ ] 弹窗内图片上传走自定义上传以携带鉴权 token，上传场景为 `small-object`，上传成功后显示预览
- [ ] 弹窗内故事输入框为纯文本多行输入，最长 2000 字，显示字数统计
- [ ] 提交前做前端提示（类型必选、图片必传、故事必填且不超长），后端仍完整校验
- [ ] Service 集成测试：保存成功（图片与故事正确落库）、同类型第二次保存被拒绝、类型不在字典被拒绝、故事超长被拒绝
