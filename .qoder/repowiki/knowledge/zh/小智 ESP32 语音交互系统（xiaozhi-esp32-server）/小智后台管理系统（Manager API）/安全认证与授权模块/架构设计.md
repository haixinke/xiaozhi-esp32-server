模块以 Apache Shiro 为核心，通过 `config/ShiroConfig` 统一装配 `SecurityManager`、`DefaultWebSessionManager`、自定义过滤器（`Oauth2Filter`、`ServerSecretFilter`）及 `AuthorizationAttributeSourceAdvisor`，并在 `filterChainDefinitionMap` 中按路径声明式绑定 `anon`/`oauth2`/`server` 等过滤规则。
- 认证流程：`Oauth2Filter` 从 `Authorization: Bearer <token>` 提取 token 并构造 `Oauth2Token`，交由 `Oauth2Realm.doGetAuthenticationInfo` 通过 `ShiroService` 查询 `SysUserTokenEntity` 和用户信息，校验有效期与状态后返回 `SimpleAuthenticationInfo`；`ServerSecretFilter` 则走另一条路径，用配置中的服务器密钥做简单比对。
- 会话上下文：`user/SecurityUser` 封装 `SecurityUtils.getSubject()` 提供 `getUser()`、`getUserId()`、`getToken()` 等静态访问点，供 Controller 直接获取当前用户。
- 分层结构：`controller/LoginController` 暴露 `/user/*` 登录/注册/找回密码接口；`service` 层定义 `CaptchaService`、`ShiroService`、`SysUserTokenService` 及其 `impl` 实现；`dao` 仅包含 `SysUserTokenDao`，用户数据由 `modules/sys` 的 DAO 提供；`entity` 存放 `SysUserTokenEntity`；`dto` 承载入参校验。
- 依赖方向：controller → service → dao；realm/filter 仅依赖 service 和 common 工具类，不反向依赖 controller，保持清晰的单向依赖。
