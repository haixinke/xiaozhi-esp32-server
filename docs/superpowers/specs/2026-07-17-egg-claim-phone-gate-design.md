# 蛋宝宝领取时手机号授权设计

## 目标

新用户完成微信静默登录后，可从欢迎页直接进入首页。手机号不再是进入首页的前置条件；仅在用户领取蛋宝宝前要求授权。手机号授权成功后自动进入现有的邀请码输入页，原有领养与孵化流程保持不变。

## 范围

- 欢迎页主按钮文案改为“进入快乐仙岛”。
- 欢迎页点击后直接进入首页，不触发微信手机号授权。
- 未绑定手机号的用户可以停留、浏览和刷新首页。
- 点击首页空态的“添加蛋宝宝”时，未绑定手机号的用户必须先完成微信手机号授权。
- 授权成功后进入现有 `pages/add-device/add-device` 页面输入邀请码；该页面继续调用既有 `/pet/adopt` 接口。
- 已绑定手机号的用户点击“添加蛋宝宝”时直接进入邀请码输入页。

## 非目标

- 不修改静默登录、token 续期、手机号绑定接口或邀请码/领养接口。
- 不新建页面、不改动已领取蛋宝宝后的孵化、破壳和聊天流程。
- 不要求用户再次勾选欢迎页隐私协议；领取时的授权按钮是明确的微信 `getPhoneNumber` 用户动作。

## 交互与数据流

```text
欢迎页
  └─ “进入快乐仙岛” → 首页

首页空态
  └─ “添加蛋宝宝”
       ├─ hasPhone=true  → 邀请码输入页
       └─ hasPhone!=true → 手机号授权弹层
                             ├─ 授权成功 → /wechat/bindPhone
                             │             → auth.markPhoneBound()
                             │             → 更新 App 登录态
                             │             → 邀请码输入页
                             └─ 拒绝/缺少 code/接口失败 → 留在首页弹层，允许重试或关闭
```

## 组件职责

### `pages/welcome`

- 保持等待静默登录的加载能力。
- 对已有有效会话直接进入首页，不再根据 `hasPhone` 区分。
- 主按钮改为普通点击按钮，调用 `switchTab('/pages/home/home')`。
- 移除欢迎页的手机号授权、绑定与默认本地用户写入职责。

### `app.js`

- 继续在启动和回到前台时恢复或刷新静默登录。
- 删除将未绑定手机号用户重启导航到欢迎页的路由守卫行为；不再限制首页或其它既有页面仅供已绑定手机号用户进入。

### `pages/home`

- 继续在静默登录完成后渲染首页，不以 `hasPhone` 作为放行条件。
- 空态“添加蛋宝宝”点击时检查当前有效会话的 `hasPhone`。
- 未绑定时显示首页内嵌授权弹层，使用 `open-type="getPhoneNumber"` 获取动态 code。
- 手机号绑定成功后持久化并同步 `hasPhone=true`，然后导航至 `pages/add-device/add-device`。
- 对拒绝授权、缺少 code 和绑定失败显示安全的用户提示，不记录 code、token 或手机号。

### `utils/auth.js` 与 `utils/wechat-api.js`

现有 `markPhoneBound()` 和 `bindPhone(phoneCode)` 接口满足需要，不改变其实现或后端契约。

## 错误处理

- 未完成静默登录或会话无效：停留在首页，显示“暂时无法连接服务，请稍后重试”。
- 用户拒绝手机号、微信未返回 code：关闭或保留授权弹层，不进入邀请码页。
- 绑定请求失败：恢复可点击状态，提示服务端安全错误文案并允许重试。
- 并发点击：授权过程进行中忽略重复操作，避免重复绑定和重复跳转。

## 测试与验证

- 欢迎页：未绑定会话和已绑定会话都可进入首页；按钮文案与普通点击跳转正确；不再调用手机号绑定。
- 应用：未绑定会话打开首页不会被重启到欢迎页；静默登录与过期会话处理保持现有行为。
- 首页：已绑定用户直接进入邀请码输入页；未绑定用户显示授权弹层；手机号授权成功后绑定并进入邀请码输入页；拒绝、缺少 code、无有效会话和绑定失败均不跳转；并发授权只执行一次。
- 运行相关 Node 单测、工程完整性校验、JavaScript 语法检查和 JSON 校验。
