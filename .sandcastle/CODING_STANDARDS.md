# Coding Standards

仅列可验证的审查约束。架构、业务规则与常用命令见根 `CLAUDE.md` 及受影响子项目的 `CLAUDE.md`，审查前必须读取。

审查范围：仅本次 diff 引入或加重的问题。可以追踪调用方和相关实现确认影响，不借机清理无关历史代码。

## 审查原则

- 以本次需求、issue/PRD、验收条件和现有接口契约判断正确性，不仅从实现推断意图
- 优先检查正确性、安全、数据一致性和兼容性，再检查可维护性
- 问题必须有具体位置、触发条件和影响；区分已确认缺陷、待验证风险与非阻塞建议
- 纯重构保持行为等价；修复已确认缺陷应保持预期业务行为，并补充回归测试
- 需求或业务规则不明确时说明缺失信息，不自行创造规则
- 本文未覆盖的子项目，按其实际技术栈和局部约定审查；不得跨目录套用框架限制

## 通用

- 变更保持单一目的；复用现有模块，不为单次调用或假设中的需求增加抽象层
- 遵循邻近代码风格；不做与本次需求无关的重命名、格式化或重构
- 保留解释业务规则、并发约束和设计原因的注释；新增注释遵循项目中文注释约定
- 不得静默丢失影响正确性的异常；允许预期取消、断连收尾和单项失败隔离；降级不能伪装成功
- 不提交密钥、凭据或私人环境配置；日志和错误响应不泄露 token、openid、登录 code、完整登录响应或其他敏感数据
- 外部输入在可信边界校验类型、长度、范围和允许值；不信任客户端提交的身份、归属、状态、金额或配额
- SQL 使用参数绑定；MyBatis 用 `#{...}`；动态表名、列名和排序字段走白名单，禁止直接拼接外部输入
- 用户输入和模型输出按不可信数据处理；涉及 HTML 渲染、文件路径或服务端 URL 访问时，检查对应的注入、路径穿越和 SSRF 风险
- 认证与授权分开；登录成功不代表可访问他人资源，前端隐藏菜单不算权限控制
- 跨端修改核对字段名、空值、大整数 ID、时间单位、时区和错误码；大整数 ID 不得转为 JS Number
- 修改现有接口核对所有受影响调用方；需要破坏兼容性时提供明确的同步升级或迁移安排
- 外部调用设置合理超时；重试必须有上限，有副作用的操作先保证幂等；失败和降级应可观察

## Python（main/xiaozhi-server）

- 新增 ASR/TTS/LLM/VAD/Intent/Memory Provider 遵循对应基类与工厂；其他 Provider 遵循其现有扩展入口
- 不得在事件循环线程直接执行 `time.sleep`、阻塞网络请求或长 CPU 任务；同步 SDK 应使用合适的线程或进程执行方式
- 会话可变状态按会话隔离；关闭时释放本会话拥有的任务、队列、连接和音频流
- 打断、取消或重连后不得发送旧轮次结果；异步及跨线程回调校验所属会话和轮次
- 音频及后台任务队列采用有界缓冲，并明确满队列时的丢弃、等待或拒绝策略
- 修改对话、意图或工具输出链路时，不得绕过既有内容安全入口和出口
- 保留内容安全 enforce/observe 模式、危机输入处理及可信兜底语义；受出口审核约束的内容不得提前进入 TTS 或持久化
- 修改配置时保持基础配置、本地覆盖、远程配置的既有优先级和缓存语义

## Java（main/manager-api）

- Controller → Service → DAO 分层；业务规则与事务边界在 Service
- 新错误码统一进入 `ErrorCode` 与 i18n；普通业务接口沿用 `Result<T>`，成功码为 `0`；协议回调遵循其协议响应格式
- 新增或修改接口时核对 Shiro 路由匹配顺序，以及用户认证、服务密钥、匿名入口的边界
- 匿名回调在产生业务副作用前完成协议要求的验签和校验；受保护资源继续校验权限及归属
- Liquibase 使用新增 changeset 并登记到 changelog 加载链；不修改已应用 changeset
- 数据库变更核对存量数据、默认值、非空和唯一约束，以及新旧应用版本的兼容性
- 幂等依赖唯一约束、条件更新或适合部署方式的锁；禁止用“先查再写”替代原子保障
- 状态流转校验预期旧状态和更新结果；重复、乱序、迟到回调不得重复扣额、重复执行副作用或使终态回退
- 避免耗时 AI/HTTP 调用长期占用数据库事务或行锁；数据库状态与外部副作用之间明确失败、重试及补偿方式
- 生图等审核链路不得提前暴露未通过审核的结果；调试旁路不得因本次变更意外在生产启用
- 定时任务和批量处理采用有界分页或批次；禁止一次性加载全表，单项失败隔离并汇总处理结果

## Vue（main/manager-web）

- 使用 Vue 2 Options API；不得引入 Vue 3 专属语法或不兼容组件
- 对已有响应式对象动态增加字段使用 `Vue.set` / `this.$set`；不直接修改 props；列表使用稳定 key
- 新用户可见文案走 vue-i18n；请求走现有 API 层，不在组件中重复实现认证和错误处理
- 处理加载、失败和空数据状态；异步响应不得覆盖较新的查询或选择结果
- 组件销毁时释放其拥有的监听器、定时器和媒体资源

## 微信小程序（main/egg-miniprogram）

- 控制 `setData` 体积和频率；音频缓冲、无展示用途的完整响应不放入页面数据
- 请求沿用现有封装；单次请求因 401 自动重登后最多重试一次，避免刷新死循环和并发重复登录
- 页面销毁或业务退出时清理其拥有的录音、WebSocket、定时器和监听器；避免误关共享资源
- 页面离开、切换对象或发起新请求后，旧异步结果不得继续更新当前页面状态
- 后端为宠物状态、资源归属和配额的事实来源；本地缓存用于回显，不作为授权或扣额依据
- 不提交私人 BASE_URL、WebSocket 地址或开发配置；经需求授权的环境迁移需核对 HTTP、WebSocket 和 OTA 链路一致性

## 测试与验证

- 开发遵循先失败测试、再实现；审查根据测试实际行为判断覆盖，不凭最终 diff 推断编写先后
- 新增或修复行为应有相关测试；缺陷回归测试应能在修复前暴露问题
- 按变更风险覆盖边界、鉴权失败、资源归属、并发幂等、重复回调、取消和失败路径
- 单元测试隔离外部 AI、网络、DB、Redis 和不可控时间；数据库约束、事务等语义需要相应集成验证，不能仅靠 mock 证明
- 执行变更相关的现有回归测试；结构检查、编译和语法检查不能替代行为测试
- 覆盖率目标至少 80%；报告必须注明统计范围、行/分支口径和实际结果，不把命令成功等同于覆盖率达标
- 不得通过删测、弱化断言或扩大跳过范围来获得通过结果
- 已知失败需要通过基线或其他可复现证据确认，不能仅凭历史文档认定与本次变更无关
- 报告实际执行的命令、结果、跳过项和未验证风险；缺依赖或外部服务时明确说明，不写“通过”
- 修改未被现有验证矩阵覆盖的代码路径时，明确补充验证方式；没有适用检查不代表验证通过
