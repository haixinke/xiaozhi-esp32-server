# 游戏分类与外部游戏跳转

Status: ready-for-agent

## Problem Statement

运营可以在智控台配置蛋宝宝小游戏及其投放入口。小程序当前只识别「一起画」「听你说」两个原生玩法。运营即使新增了可玩的 H5 游戏，也无法配置它的跳转链接。用户从百宝箱活动或小纸条点击其他游戏时，只会看到未开放提示。

## Solution

在游戏管理中增加「游戏分类」和「跳转链接」。运营通过现有游戏入口配置，将外部游戏投放到百宝箱「活动」、首页「小纸条」或两处。用户点击内部游戏时进入原生玩法，点击外部游戏时在蛋宝宝小程序的 `web-view` 中打开 H5。外部游戏免费、不限次、无游戏星星奖励，小纸条自身的连续奖励照常发放。

## User Stories

1. 作为运营人员，我希望在游戏列表中看到内部游戏和外部游戏，以便确认每条配置的打开方式。
2. 作为运营人员，我希望新增游戏时选择游戏分类，以便在同一个管理入口配置原生玩法和 H5 玩法。
3. 作为运营人员，我希望继续从现有游戏类型字典选择玩法，以便沿用现有名称、标识和唯一性规则。
4. 作为运营人员，我希望编辑外部游戏时看到已保存的跳转链接，以便更新地址或核对投放配置。
5. 作为运营人员，我希望漏填链接或填写无效链接时看到提示，以便在启用前修正配置。
6. 作为运营人员，我希望编辑内部游戏时只看到适用的配置项，以便继续设置现有星星和次数规则。
7. 作为运营人员，我希望外部游戏自动使用零奖励、零费用和无限次配置，以便用户看到的权益与实际玩法一致。
8. 作为运营人员，我希望能单独选择百宝箱「活动」或首页「小纸条」，也能同时选择两者，以便按运营计划投放同一个外部游戏。
9. 作为运营人员，我希望停用外部游戏后能重新启用并沿用原链接和入口，以便临时下架期间保留配置。
10. 作为运营人员，我希望「一起画」和「听你说」固定为内部游戏，以便保留现有原生体验。对应的 H5 版本可使用独立的游戏类型上架。
11. 作为活动页用户，我希望点击外部游戏后直接在蛋宝宝小程序内开始玩，以便无需切换到其他应用。
12. 作为小纸条用户，我希望点开纸条中抽到的外部游戏，以便参与当天邀请的玩法。
13. 作为小纸条用户，我希望按照现有规则获得打开纸条的连续奖励，以便奖励与抽到的游戏分类无关。
14. 作为外部游戏玩家，我希望打开的链接能保留运营设置的查询参数和页面锚点，以便到达对应关卡或活动页。
15. 作为外部游戏玩家，我希望加载失败时看到清楚的提示并能返回，以便继续使用小程序。
16. 作为外部游戏玩家，我希望可以重复打开 H5，以便游玩时没有蛋宝宝星星扣费或每日次数门槛。
17. 作为内部游戏玩家，我希望两个入口继续打开原生玩法，以便现有局次、星星和结算体验照常运行。
18. 作为仍在使用旧版小程序的用户，我希望已上架的原生玩法继续按原有类型打开，以便在升级前继续游玩。
19. 作为维护人员，我希望迁移存量游戏时自动填充内部分类，以便部署时无需逐条修改运营记录。

## Implementation Decisions

### 后端服务

- 保留 `GAME_TYPE` 字典以及一个游戏类型对应一条配置的约束。新增游戏分类 `gameCategory`，可取 `INTERNAL` 或 `EXTERNAL`。`DRAW_TOGETHER` 和 `LISTEN_TO_YOU` 只接受 `INTERNAL`。
- 通过 Liquibase 为 `ai_game` 增加非空 `game_category`，默认和存量值均为 `INTERNAL`，以及可空 `jump_url`。升级时保留现有游戏类型、星星配置、每日上限、游戏入口和启用状态。
- 管理端沿用现有新增、更新、分页和详情接口。新增请求缺少分类时按内部游戏处理。旧版客户端更新时若缺少分类，保留该记录已保存的分类和链接，并按其分类校验更新后的配置。显式保存为内部游戏时将链接清空。
- 外部游戏的 `jumpUrl` 由后端校验。去除首尾空白后，必须是含有效主机名的完整 HTTPS URL，不能嵌入用户名或密码。保留合法查询参数和片段；后端只校验配置格式，域名准入由微信业务域名控制。
- 外部游戏的 `earnStars`、`consumeStars`、`dailyLimit` 均为 `0`，后端拒绝违反此约束的写入。一起画和听你说的局次、额度与结算沿用现有约定。
- `/app/game/list` 的游戏项与 `/app/daily-note/today` 的嵌套 `game` 使用同一游戏响应模型，新增 `gameCategory` 和 `jumpUrl`。沿用启用状态与游戏入口筛选，以及小纸条从可用游戏中随机选择的规则。

### 智控台

- 游戏列表展示游戏分类。新增默认选中「内部游戏」，编辑时回显已保存的分类和链接。
- 选择「外部游戏」时显示并校验「跳转链接」，星星奖励、扣费和每日次数固定为 `0`。选择内部游戏时隐藏链接输入。对「一起画」「听你说」只允许选择内部游戏。
- 活动、小纸条的多选沿用现有交互，仍至少选一个。启用、停用及编辑均保留当前分类和对应链接。

### 蛋宝宝小程序

- 百宝箱活动与首页小纸条都先识别游戏分类。外部游戏进入同一个 `web-view` 页面，URL 经路由后完整还原，小程序凭证和账号信息不随链接传递。
- 内部游戏按现有游戏类型分流，旧响应缺少分类时沿用这一行为。一起画继续携带活动或小纸条来源，听你说继续打开原生答题页。尚未实现的内部游戏保留各入口原有的未开放提示。
- 沿用现有破壳和手机号门槛。无效链接或打开失败时给出可理解的提示，用户可留在入口或返回。打开 H5 不产生游戏结算、扣费或次数记录，打开小纸条的连续奖励由现有流程发放。

## Testing Decisions

测试从现有调用入口验证可观察行为，重点检查保存与查询结果、可见页面状态和实际导航。沿用现有自动化测试入口，再进行一次微信真机验收。

- **后端游戏服务及现有小程序读接口。** 参照现有游戏管理服务测试、当日小纸条服务测试与 Liquibase 测试惯例。验证存量数据迁移、外部游戏的保存与读取、编辑和启停往返、外部转内部清空链接、旧请求兼容以及内置类型保护。覆盖未知分类、外部缺少链接、非法 URL 和非零结算字段。验证两个读接口正确返回分类及链接，且停用后不再分发。涉及数据库的用例使用隔离测试数据。
- **智控台游戏管理交互。** 沿用运营管理表单的现有测试结构，覆盖新增默认值、不同分类下字段约束、编辑回显、切换分类及启停时提交完整配置。
- **蛋宝宝小程序活动和首页的点击行为。** 在现有活动页、首页测试中覆盖两处入口的外部分流、带参数与片段的地址、异常提示、存量响应的原生路由、一起画的来源标记及独立的小纸条打开领奖。新增页面纳入现有工程完整性校验。
- **微信真机。** 用一个已配置业务域名的 HTTPS H5，从活动和小纸条实际打开，确认加载、查询参数和返回路径；复查内部游戏可从原入口打开。真机验收使用正常的业务域名校验。

## Out of Scope

- 开发、托管或改造 H5 游戏内容。
- H5 与蛋宝宝之间的账号打通、游戏进度同步、完成回调或星星及次数结算。
- 增加新的游戏入口、修改小纸条抽取规则或调整原生游戏的星星与局次规则。
- 自动配置微信公众平台业务域名。

## Further Notes

- 先上线后端迁移和新版小程序，再由运营启用外部游戏。尚未更新的小程序会对这些独立的外部游戏类型显示原有的未开放提示。
- 运营配置的目标 H5 域名需完成蛋宝宝小程序业务域名的验证和配置。[腾讯云小程序业务域名配置指南](https://cloud.tencent.com/document/product/1301/100434)
- 领域术语见 [术语表](../../GLOSSARY.md)。原生玩法的局次归属与结算遵循 [ADR 0011](../../docs/adr/0011-drawing-user-session.md)。
