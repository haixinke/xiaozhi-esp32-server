- 每个厂商实现一个继承自 `LLMProviderBase` 的 `LLMProvider` 类，并重写 `response` 与可选的 `response_with_functions` 方法。
- 所有 Provider 在 `__init__` 中通过 `check_model_key('LLM', self.api_key)` 校验 API Key，并使用 `setup_logging()` 获取 logger，配合 `TAG = __name__` 进行日志打点。
- `response` 必须返回生成器，按 token 增量 yield 文本；`response_with_functions` 需 yield `(content, tool_calls)` 二元组，不支持函数调用的 Provider 回退为始终 yield `(token, None)`。
- 请求参数采用“必填 + 可选”分离模式：先构造基础参数字典，再遍历 `kwargs` 或实例属性将非 `None` 的可选参数合并进去。
- 流式响应使用 `try/finally` 确保客户端连接或 SDK stream 被关闭，避免资源泄漏。
