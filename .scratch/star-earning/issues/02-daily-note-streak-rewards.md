# 02: 小纸条连续奖励与统一每日奖励能力

**What to build:** 用户通过现有小纸条打开接口首次打开当日内容后，星星自动进入星星罐：首次11颗，连续每天增加1颗，最高17颗，中断后恢复11颗。当天重复打开、跨宠物或设备重试均不重复发奖。该链路同时交付可供其他游戏复用的每日奖励资格与入账能力。

**Blocked by:** None (can start immediately).

**Status:** resolved

## Comments

完成（commit ae11f663，merge 23263ba4）：新增 `ai_star_daily_reward` 表（Liquibase changeSet 202610301000，按 spec DDL）+ 统一每日奖励服务 `StarDailyRewardService.claimDailyReward(userId, sourceType, sourceKey)`（DAILY_NOTE/GAME 来源、账户行锁串行化、北京时间、幂等返回原记录）。小纸条打开接口编排打开记录+奖励+钱包同事务提交，历史打开记录不参与连续计算。22 个新测试全绿，定向 85 全绿，全量 1092 run 9 errors 均基线既有；jacoco 相关类 ≥80%。注意：GAME 来源当前沿用连续公式，ticket 03 需加固定金额变体。

- [x] 仅新增已确认的每日奖励表 ai_star_daily_reward，通过 Liquibase 追加迁移，不修改已有迁移。
- [x] 表包含雪花主键、用户ID、来源类型、来源标识、领取日期、实际奖励数量、星星流水ID、创建时间；字段类型和非空规则遵循已确认的 spec。
- [x] 用户、来源类型、来源标识、领取日期组成每日唯一约束；星星流水ID另有唯一约束。来源字符串使用后端规范值，不能因大小写差异形成两份资格。
- [x] 不增加游戏完成事件单号字段、连续天数表、独立游戏结算表、宠物或设备维度字段；不建物理外键及无实际查询需求的日期单列索引。
- [x] 提供可复用的每日奖励能力，统一负责用户与来源的当天资格、并发防重及调用现有钱包；小纸条连续金额由业务侧计算，不塞入钱包基础接口。
- [x] 所有日期由后端按 Asia/Shanghai 自然日确定；首次成功领取为11颗，昨天有成功奖励则今天增加1颗并封顶17颗，昨天无成功奖励则恢复11颗。
- [x] 连续第1至第8天奖励为11、12、13、14、15、16、17、17颗；封顶后持续17颗，中断一天后再次领取11颗。
- [x] 每用户每日仅获得一份小纸条奖励，切换宠物、设备、重复请求或并发请求均不重复发奖，也不增加连续天数。
- [x] 保持现有小纸条打开接口的地址、无请求正文契约、认证用户来源和成功空响应结构；不接受客户端传入用户身份、奖励金额或领取日期。
- [x] 无当日小纸条时沿用现有成功空操作，不写打开状态或发奖；有当日内容且请求有效时，即使没有可用推荐游戏也可发奖。
- [x] 已存在的历史打开记录不参与连续计算、不补发；上线当天已经打开的用户跳过当天奖励，从次日首次有效打开开始领11颗，当天尚未打开者可正常领取11颗。
- [x] 首次打开记录、奖励记录、资金流水和余额在同一事务提交，任一步失败整体回滚；失败重试可正常领取，不能留下新打开状态阻断补偿。
- [x] 同用户奖励结算使用数据库事务与账户行锁串行化，锁内使用当前读并确定北京时间日期，避免并发和可重复读旧快照造成错误金额或重复入账；每日唯一约束作为兜底。
- [x] 奖励记录与流水一对一关联，保存实际金额快照；纸条内容覆盖、删除、同日重建不重置已领取资格。
- [x] 小纸条使用独立奖励来源和钱包业务类型，避免与现有签到或其他游戏的业务单号相互冲突。
- [x] 先写失败测试再实现；覆盖递增、封顶、重置、北京时间日界、用户隔离、历史兼容、无内容、无游戏、重复并发请求及事务失败回滚后重试。
- [x] 使用替换时钟验证日期边界；数据库集成测试验证实际记录、余额和流水一致性及并发行为，不能仅凭 mock 调用次数宣称事务正确。
- [x] 运行相关服务、HTTP 契约及后端全量测试，相关服务有效覆盖率目标80%以上；测试数据独立并清理，明确报告既有失败。
- [x] 仅修改后端，不修改小程序或智控台前端，不宣称现有小程序点击触发已验证，不接入具体游戏完成流程。
