## Problem Statement

运营需要维护蛋宝宝的「小纸条」：每个完整日期最多一份内容，可以批量导入和修正。未来小程序需要按用户当天的查看状态提供小纸条，并附带一个可从小纸条入口进入的游戏；同一用户当天打开后，不应在其他设备上再次看到。

目前后端没有小纸条内容、已打开状态或当日接口。智控台已有游戏配置及「小纸条」游戏入口，但尚无消费该入口的小纸条能力。本次交付后端和智控台，蛋宝宝小程序页面后续单独接入。

## Solution

在智控台「运营管理」下新增独立的「小纸条管理」。运营可以分页浏览、按完整日期查询、新增、编辑和物理删除小纸条，也可以通过 JSON 文件批量新增或按日期覆盖。

后端提供当日查询和标记已打开接口。当日查询由服务器按 `Asia/Shanghai` 判断日期；当日内容和随机小纸条游戏必须同时存在，否则成功返回空对象。已打开状态按用户和完整日期隔离，跨设备生效，重复上报幂等。

## Implementation Decisions

### 交付边界

- 新增独立的小纸条后端业务模块，复用项目现有 Controller、Service、DAO、DTO、VO 和统一响应分层。
- 智控台新增小纸条管理页面、API 封装、路由和「运营管理」菜单接线。
- 数据库通过 Liquibase 新增变更，只追加 changeSet，不修改既有 changeSet。
- 不修改蛋宝宝小程序；后端接口作为后续接入契约。
- 沿用 ADR 0006 的删除背景及 ADR 0010 对纯运营内容物理删除的既有决策方式。小纸条无软删或回收站，用户已打开记录独立保留。

### 小纸条数据模型

- 每份小纸条包含完整日期、标题、正文、可选节气和审计字段。
- 内容表名为 `ai_daily_note`，字段确定为：`id BIGINT` 主键（雪花 ID，非自增）、`note_date DATE NOT NULL`、`title VARCHAR(50) NOT NULL`、`content VARCHAR(200) NOT NULL`、`solar_term VARCHAR(50) NULL`、`creator BIGINT NULL`、`create_date DATETIME NULL`、`updater BIGINT NULL`、`update_date DATETIME NULL`。
- 内容表只有主键和 `UNIQUE KEY uk_ai_daily_note_date (note_date)`；日期唯一索引同时支撑当日查询，不另建年份、月份、状态、版本或软删字段。
- 同日覆盖保留 `id`、`creator`、`create_date`，更新四个内容字段及更新审计字段。
- 日期使用数据库 `DATE` 语义，不使用日期时间截断模拟，也不按服务器默认时区解释。
- 完整日期全局唯一；一个日期只有一份小纸条，不按年循环。
- 标题和正文必填；节气可空，不计算、不翻译、不限制为标准二十四节气。
- 保存前对三个文本字段去除首尾空白；正文内部换行保留，按纯文本而非 HTML 或 Markdown 处理。
- 长度按 Unicode 字符数而非 UTF-8 字节数校验：标题 50、正文 200、节气 50。
- 手工保存拒绝目标日期已存在的记录；编辑自身不视为冲突。
- 物理删除不级联删除游戏或已打开记录。

### 用户已打开数据模型

- 已打开记录包含用户 ID、小纸条完整日期和首次打开时间。
- 已打开表名为 `ai_daily_note_opened`，字段确定为：`id BIGINT` 主键（雪花 ID，非自增）、`user_id BIGINT NOT NULL`、`note_date DATE NOT NULL`、`opened_at DATETIME NOT NULL`、`create_date DATETIME NULL`。已核实后台用户和微信用户主键均为 `BIGINT`。
- 已打开表只有主键和 `UNIQUE KEY uk_ai_daily_note_opened_user_date (user_id, note_date)`；没有按日期查询全部用户的需求，不增加 `note_date` 单列索引。
- 不保存 `note_id`，不建外键；内容覆盖、删除或同日重建均不影响该用户在该日期的已打开状态。历史已打开记录永久保留，本期不清理。
- 用户 ID 与日期组成联合唯一约束，不依赖小纸条 ID 或内容版本。
- 不设置外键级联，物理删除或覆盖小纸条不清除已打开记录。
- 首次写入后重复请求不更新首次打开时间。
- 仅当有当日小纸条时写入；此时不要求游戏可用。
- 无当日小纸条时标记接口成功但不写记录，已有记录则保持幂等成功。

### 当日查询与游戏选择

- 提供认证后的 `GET /app/daily-note/today`，无请求日期参数；服务器以 `Asia/Shanghai` 得到当天完整日期。
- 提供认证后的 `POST /app/daily-note/opened`，无请求正文；用户 ID 从 Token 获取，日期同样由服务器决定。
- 两个接口沿用现有应用端普通用户权限和统一 `Result` 信封。
- 查询先确认当日小纸条存在且当前用户没有该日已打开记录，再获取游戏。
- 游戏复用现有游戏服务的启用状态和 `NOTE` 入口过滤能力，不新增游戏入口枚举，不复制游戏配置。
- 从合格游戏中每次重新随机选择一个；停用、删除或移除入口后的游戏不再参与。
- 小纸条或合格游戏任一缺失时，返回 `code=0, data=null`，不返回部分对象。
- 成功响应仅含 `date`、`title`、`content`、`solarTerm`、`game`；不暴露小纸条 ID 或后台审计字段。
- `game` 复用现有 `GameVO` 结构；标记接口成功返回统一空数据结果。

### 管理接口与页面

- 管理接口使用独立 `/admin/daily-note` 前缀，全部要求现有超级管理员权限。
- 提供分页列表、按 ID 详情、新增、编辑、按 ID 删除和 JSON 导入能力。
- 分页默认按日期倒序，可选完整日期精确过滤；列表包含日期、标题、节气、正文摘要、更新时间。
- 新增和编辑共用表单；编辑展示完整正文。
- 删除确认展示日期、标题及不可恢复说明。
- 页面不提供上下架、审核、定时发布、回收站或恢复功能。

### JSON 导入契约

- multipart 字段名为 `file`，文件必须是 UTF-8 编码的 `.json`，最大 1 MB。
- 顶层为非空数组，最多 1000 项；每项只能是包含以下字段的对象：

  | 字段 | 类型 | 必填 | 规则 |
  |---|---|---|---|
  | `date` | 字符串 | 是 | 严格 `yyyy-MM-dd`，必须是真实存在的完整日期 |
  | `title` | 字符串 | 是 | 去首尾空白后 1–50 字 |
  | `content` | 字符串 | 是 | 去首尾空白后 1–200 字，保留内部换行 |
  | `solarTerm` | 字符串或 null | 否 | 去首尾空白后最多 50 字，可为任意文案 |

- 除上述字段外，未知字段整批拒绝；不接受别名、嵌套结构、单对象顶层或额外元数据。
- 导入数组行号使用从 1 开始的位置，与 JSON 数组顺序一致。
- 示例文件：

  ```json
  [
    {
      "date": "2026-10-29",
      "title": "今日小纸条",
      "content": "今天也辛苦了。\n记得早点休息。",
      "solarTerm": "霜降"
    },
    {
      "date": "2026-10-30",
      "title": "给自己的一句话",
      "content": "慢慢来，也很好。",
      "solarTerm": null
    }
  ]
  ```

- 文件内相同 `date` 直接整批拒绝，不采用第一条或最后一条。
- 校验失败一次返回可发现的行号、字段和原因，全部零写入。
- 校验通过后在单个数据库事务内写入；库内同日期整项更新内容，其余日期新增。
- 同日覆盖保留记录身份和创建审计信息，更新内容、更新人和更新时间；不触碰已打开记录。
- 导入成功返回 `addedCount` 和 `overwrittenCount`。
- 数据库唯一键冲突、写入异常或其他运行时失败均整批回滚，并向运营返回可理解的错误，不泄露 SQL 或堆栈。

### 并发与错误处理

- 小纸条日期唯一约束兜底手工保存、导入和并发写入。
- 已打开采用先查后插并处理唯一键冲突；并发冲突视为成功，原记录和首次时间不变。
- 并发导入若发生日期唯一键冲突，返回明确的日期冲突错误并整批回滚；不宣称阻塞所有并发，也不产生部分成功。
- 所有查询和保存使用参数化 ORM/SQL，不拼接用户输入。
- 错误使用项目统一业务错误码与国际化消息，新增独立号段，不复用题库错误码。

## Testing Decisions

### 测试原则与接缝

- 测试外部可观察行为，不依赖内部私有方法、随机实现细节或 SQL 语句形状。
- 后端业务主接缝是公开 Service 接口：输入业务参数或上传文件，断言响应、数据库状态和业务异常。
- 后端 HTTP 契约接缝使用仓库已有 MockMvc 先例，验证认证用户上下文、路由、成功空响应及统一错误结构；不重复 Service 的全部分支。
- 随机行为通过多次从两个合格游戏中抽取并断言观察到两者来验证，不要求固定随机序列；游戏过滤单独用确定性用例验证。
- 时间边界通过可替换时钟或既有时间抽象验证 `Asia/Shanghai` 日界，不让测试依赖真实午夜。
- 测试数据独立并在结束后清理，不修改或删除运营既有数据。

### 后端测试范围

- 管理 Service：分页与日期过滤、完整字段保存、新增编辑、日期冲突、长度与空白校验、物理删除。
- 导入 Service：新增与覆盖计数、同日整项覆盖、未涉及记录不变、文件内重复、未知字段、空数组、非法 JSON、非 UTF-8、错误扩展名、大小和条数限制、逐行错误明细、校验失败零写入、数据库失败回滚。
- 当日 Service：完整日期匹配、不跨年复用、已打开返回空、不同用户隔离、次日隔离、无小纸条或无合格游戏返回空、游戏启用与 `NOTE` 过滤、两游戏随机覆盖、游戏变更后实时生效。
- 已打开 Service：重复请求幂等、首次时间不变、无当日内容不写记录、无游戏时仍可记录、覆盖/删除/重建不重置、并发唯一键冲突视为成功。
- HTTP：两个应用接口的 Token 用户传递与空响应，管理接口的权限和统一错误结构。
- 参考现有游戏管理 Service 集成测试、题库导入 Service 集成测试、物理删除测试和 MockMvc Controller 测试。
- 先写失败测试再实现；关键业务分支必须覆盖，以服务层有效覆盖率而非琐碎 getter 充数，目标 80% 以上。

### 智控台验证

- 不新增 Playwright 自动化测试。
- 保留并运行现有 Node 单元测试，覆盖路由、菜单和 API 接线可测试的部分；运行 Vue 模板检查和生产构建。
- 交付人工测试清单：菜单可见性、分页和日期查询、新增编辑校验、重复日期提示、删除确认、JSON 新增/覆盖/失败反馈、导入结果统计。

## Out of Scope
